# GitLab 本地 CI 日志附件

自动 MR 本地 CI 结束后，导出已有完整运行记录并上传到对应 GitLab 项目。文件包含提交、起止时间、步骤命令、退出码、准备过程及完整 stdout/stderr 输出，不能拿有界末尾输出冒充完整日志。历史记录缺少逐块输出时明确标记证据不完整。

GitLab external 状态的 target_url 使用项目附件地址；等待和运行阶段没有最终附件，不提供管理后台链接。失败评论和诊断更新均保留相同附件入口。GitHub 状态回写保持当前行为，不引入 GitLab Runner 或仓库 CI 配置变更。

按 CI 运行 ID 与实际执行尝试次数持久化上传状态和地址，使用资源租约防止并发重复上传。已成功的附件跨重启、状态补发和结果复用直接复用；基础设施重试的新执行不能复用上次执行的日志附件。请求在限定总时长内最多尝试三次，权限错误和文件过大不重试。上传失败独立保存、写入 CI 运行日志，不改变测试结果，也不回退到管理员 UI。

导出在临时文件中流式进行，并对仓库、全局配置及 Provider 已知凭据进行跨日志块脱敏。上传只访问当前 GitLab，附件地址校验同源且为 uploads 路径。附件受 GitLab 项目的访问规则管理；本地历史清理不删除远端附件。网络超时且服务端已经接收文件的情况下，重试可能留下重复附件，无法用本地去重保证远端严格仅一次。
