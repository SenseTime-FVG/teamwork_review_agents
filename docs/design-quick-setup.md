# 仓库快速配置向导

## 用户流程

运行概览和仓库页提供“一键配置”。五步分别为平台、仓库与 Token、规则、Skill、检查与完成。不选择模型，也不创建固定模板规则；动态展示当前事件规则和定时规则，沿用关联 Agent 的模型、Prompt 和权限。

GitHub、GitLab 使用默认 API 地址，自定义用于指定 GitHub Enterprise / 自建 GitLab 地址。HTTPS Token 与 SSH 密钥分别验证，拒绝在带用户密码、查询串或明文 HTTP 的地址上传递 Token。凭据存为仓库环境变量，Secret 开、Prompt 关、进程开；沿用现有配置的 Secret 脱敏与历史记录机制，不返回真实 Token。

## 规则范围

每条规则单独计算新仓库是否适用。原启用且范围为空表示全部：勾选保持全部，取消则展开为此前所有仓库的白名单（包括暂时停用的仓库，保留其原有适用关系）。原白名单加入或移除当前仓库，不自动将白名单压缩为全部，以免改变未来仓库的默认行为。原关闭的规则若被勾选，只为当前仓库启用；没有任何适用仓库时关闭规则，不能把空列表作为“零仓库”。

已有同平台、同项目仓库可在向导中明确选择更新；保留身份、本地目录及其他设置。不允许隐式创建重复仓库。保存只影响当前仓库的规则关系，不修改既有任务。

## Skill 隔离

不使用 Skill 对应仓库禁止所有 Skill。选择已有 Skill 或引用服务端已有 Skill 目录；按关联 Agent（包含允许调用的 sub-agent）指定。新增仓库级 `agent_skills` 覆盖，仅替换该仓库中指定 Agent 的装载列表，之后仍受 `allowed_skills` 限制。共享 Agent 不被修改；Agent 重命名或删除同步维护引用。

## 保存和检查

向导期间只维护内存草稿。预览使用与保存相同的服务端配置构造器；可分别检查平台仓库读取和 Git 远端读取，不发评论、不克隆仓库、不运行 Agent。检查成功只表示读取通路可用，不声称有合并或推送权限。

Git 检查使用与基础仓库一致的临时凭据程序，`GIT_ASKPASS` 只指向可执行脚本。已知 Git 故障会显示脱敏、限长的具体摘要，帮助区分凭据程序无法启动、认证失败、网络/TLS 和超时；平台 API 及未知异常仍使用固定提示，避免泄露请求和响应中的凭据。

完成配置时在配置锁下验证版本并原子保存平台连接、仓库、Token、Skill 注册和规则范围。版本冲突要求重新打开向导，不覆盖并发修改。保存后按所选规则正常调度，不额外立即触发任务。直接输入的 Token 与现有固定值配置相同，会写入本地 config.yaml；界面明确说明并提供宿主机环境变量引用选项。
