# Codex 请求版本刷新设计

## 原因与目标

内嵌 Codex Responses 客户端永久缓存 CLI 版本。后台持续运行期间升级 CLI，模型目录查询使用新版 CLI，但推理请求仍携带旧版 `version`，使上游拒绝新版模型。

每次新的模型请求读取当前实际 CLI 版本，不需要为了吸收后续 CLI 升级而重启后台。模型目录查询及已有模型配置保持不变。

## 请求边界

- 在 `create_response` 开始时异步在线程中执行版本探测，避免阻塞事件循环。
- 本次请求的网络重试和 401 凭据刷新共用同一版本快照，`version` 与 `User-Agent` 保持一致。
- 下一次模型请求重新探测，不保留进程级版本缓存；仍遵守现有运行绑定的可执行文件路径。
- 找不到程序、探测超时、非零退出或无法识别版本时明确报错，不再发送 `unknown`。不输出原始探测日志或凭据，不将本地版本故障当作模型故障重试。

## 验证

覆盖同一客户端连续请求期间 CLI 版本更新、同一请求重试及凭据刷新、线程探测不阻塞事件循环，以及失败时不发送 HTTP 请求。既有模型错误识别与隐藏子进程窗口策略继续通过回归测试。

本次代码部署需要重启旧后台加载修复；重启前检查运行中的任务，避免中断 Agent。
