# Agent 工作区 Python 测试环境

## 目标与边界

复用仓库的 `agent_workspace.prepare_steps` 安装项目与测试依赖，不针对某个 Agent 或依赖包增加特例，不自动猜测包管理器，也不向宿主 Python 安装依赖。依赖安装仍由管理员配置的命令在现有沙盒、网络权限和超时边界内执行。

新增可选的 `python_venv`（仓库内相对目录）和 `python_check_modules`（启动前需要导入验证的模块列表）。未配置虚拟环境时保持原有行为；模块列表只做显式校验，不据此自动安装软件。

## 环境接入

准备或快照恢复后，校验虚拟环境目录没有逃逸当前工作区，解释器存在，并通过真实进程确认 `sys.prefix` 指向该虚拟环境。配置的模块必须能够导入。校验使用与准备步骤相同的沙盒和受控环境，不能绕过权限限制。

校验成功后，将虚拟环境入口置于后续命令 `PATH` 的最前端，设置 `VIRTUAL_ENV`，清除会干扰虚拟环境的 `PYTHONHOME`。运行时提示明确提供解释器绝对路径与 `python -m pytest` 测试入口，说明缺依赖造成的收集错误属于环境未就绪，不能当作已确认的代码测试失败或测试通过。此信息适用于全部模型运行器和所有 Agent，不修改具体审核 Prompt。

继承父工作区的子 Agent 不重复安装，但仍校验并接入同一环境；使用独立工作区的 Agent 独立准备。子 Agent 校验失败时不重建共享环境，避免影响父 Agent 或并行子 Agent。

## 快照与失败

虚拟环境路径和校验模块加入准备签名。快照恢复后不直接认定环境可用；检查 Python 解释器及入口脚本，拒绝指向旧工作区的 Python 脚本入口。校验失败时废弃该快照，并仅重新执行一次已配置的准备命令；再次失败即停止，不继续循环恢复或静默使用宿主 Python。

快照恢复、重新准备与校验共享准备总超时。取消和超时沿用原有状态。普通安装失败标记为环境准备失败；确定性的 Python 环境校验失败附带错误码且不自动从头重试。准备失败不启动模型、不执行测试，不发布代码通过结论。

日志记录校验来源、解释器、Python 版本、模块检查和环境错误。管理界面增加两个可选配置项，并明确展示“环境未就绪，测试未执行”；原始命令输出和退出码保留。不会改变远端 CI 基线关联逻辑，也不会重放历史审核。
