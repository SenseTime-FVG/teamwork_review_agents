# 原对话副本压缩设计

## 已确认需求

- 从当前完整活跃对话 fork 独立副本，在副本末尾追加交接请求，不先打包为 JSON 参考资料。
- 默认自动压缩阈值改为完整模型窗口的 90%；已有显式配置不覆盖。
- 提示词采用进展与决策、背景与约束、待办与下一步、关键资料与引用四类交接内容；禁止工具调用，下一步遵循用户最新要求，不针对某个 Agent。

## 消息与执行边界

副本保留原 `instructions`、原始任务、已有摘要、模型消息、工具调用和工具结果的结构、顺序、标识及当前协议可发送的推理项。继承当前 Provider、模型、推理参数和工具定义，强制 `tool_choice=none`，仅解除原任务输出 Schema。副本使用独立模型请求，不创建新的 Agent、进程或 Git 分支。

摘要消息只追加到副本；原历史在完整摘要通过预算验收之前不变。失败、取消、空摘要、未完整结束、返回工具调用时不提交草稿、不执行工具。成功后仍保留固定系统指令、原始任务与近期完整回合，用摘要替换较早历史。原有运行日志及工具结果文件机制不变。

“完整上下文”指当前活跃历史；曾压缩的旧历史以已有摘要参与，不重新读全量历史日志。保留消息结构不能保证摘要语义绝对准确。

## 预算与失败

默认阈值为 `window * 0.90`，同时受输出预留和追加交接/收短提示开销约束。保守 UTF-8 预算算法、软摘要目标及有界收短设置继续兼容。超过软目标不失败，仅按整体预算和实际缩小效果验收。

完整 fork 请求装不下窗口时报告 `context_summary_request_too_large`，保留原历史。不再偷偷降级成 JSON 分片、截断工具结果或丢弃消息。切换小窗口模型也遵守此规则。收短时从同一份原对话副本重新生成，仅修改末尾请求，不把失败草稿作为新的历史。

## 协议与可观测性

Responses 与 Chat Completions 使用 `tool_choice=none`；Anthropic 与 Gemini 映射到对应禁用工具选项，并保持现有消息转换。运行器拒绝任何摘要工具输出，作为第二道执行保护。

协议依据：[Anthropic 工具选择](https://platform.claude.com/docs/zh-CN/agents-and-tools/tool-use/define-tools) 的 `none` 与 [Gemini 函数调用配置](https://ai.google.dev/api/caching#FunctionCallingConfig) 的 `NONE`。

诊断标识 `summary_context_mode=fork`，记录实际触发阈值、追加提示预留量、请求大小、摘要大小及收短次数，不记录原指令、密钥或加密推理。日志不再声称使用 JSON 参考资料/分片摘要。
