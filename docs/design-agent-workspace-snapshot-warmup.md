# Agent 工作区依赖快照与预热设计

## 目标

仓库已经可以在模型启动前执行用户定义的 `prepare_steps`，并共享包管理器下载缓存。但每个独立 Agent 工作区仍要重新生成 `node_modules`、虚拟环境等安装产物，继承父工作区的 sub-agent 也会重复执行准备步骤。

本功能在不修改 Prompt、不猜测包管理器的前提下，为准备步骤增加自动依赖快照和仓库页手动预热：

- 首次 Agent 运行在快照未命中时正常执行准备步骤，成功后自动创建快照；
- 后续隔离工作区命中快照时直接恢复准备产物；
- 继承父工作区的 sub-agent 复用父运行已经完成的准备结果；
- 管理员可在仓库页提前对默认分支执行“预热准备”，避免首次 Agent 等待安装。

## 指纹与共享边界

快照仍按稳定仓库身份隔离，不同仓库不共享。仓库内部不按分支名分目录，而按准备指纹共享；同一依赖状态的多个分支可命中同一份快照。

准备指纹包含：

- 快照格式版本；
- `prepare_steps` 的名称、工作目录、参数数组和超时配置；
- 操作系统、CPU 架构和 Python 运行时；
- 准备步骤可执行程序的解析路径及文件元数据；
- 仓库中常见依赖描述文件和锁文件的相对路径及内容摘要。

锁文件、准备命令、运行平台或工具版本变化都会产生新指纹。旧快照不会被错误覆盖，并由仓库级 LRU 策略清理。

## 快照内容

Teamwork 不硬编码 `npm ci`、`uv sync` 等安装语义。准备成功后，通过 Git 查询本次工作区新增且未被版本控制的文件，包括正常未跟踪文件和 `.gitignore` 忽略文件，并将它们保存为安全归档。恢复时只允许写入当前工作区内部，拒绝绝对路径、父目录跳转以及逃逸工作区的链接。

快照不会保存或覆盖 Git 已跟踪文件，避免旧分支源代码覆盖新工作区。下载缓存继续使用现有仓库级缓存目录，依赖快照是其下的独立区域。

## 自动懒初始化

Agent 工作区准备顺序调整为：

1. 创建或继承当前运行工作区；
2. 计算准备指纹；
3. Executor 明确标记继承父 Agent 工作区的 sub-agent，直接复用父运行已完成的准备结果；
4. 独立工作区若存在有效快照，安全恢复并跳过准备命令；
5. 快照缺失或恢复失败时执行完整 `prepare_steps`；
6. 准备成功后创建快照；
7. 启动模型。

恢复失败必须回退到完整准备步骤，不能仅因缓存损坏阻止 Agent。准备命令自身失败时仍保持现有失败行为，不创建快照也不启动模型。

## 手动预热

仓库详情“Agent 工作区准备”标题区域增加“预热准备”操作。手动预热：

- 更新基础仓库并检出远端默认分支的临时隔离 worktree；
- 使用与真实 Agent 相同的仓库环境、下载缓存、指纹和准备执行器；
- 快照命中时完成验证，未命中时执行准备步骤并创建快照；
- 不触发 Agent、不修改 Prompt、不回写 GitHub / GitLab 状态；
- 完成后清理临时 worktree。

页面展示未准备、准备中、已就绪、已过期和失败状态，并在准备期间轮询步骤与有界实时日志。手动预热是优化入口，不是运行前置条件；管理员没有点击时，首次 Agent 仍会自动初始化。

## 容量与清理

每个仓库最多保留最近三份依赖快照，并设置五 GiB 的仓库级快照空间上限。每次命中都会刷新最近使用时间；创建新快照后按最近最少使用顺序清理，始终优先保留刚创建或刚命中的快照。

快照元数据记录指纹、创建时间、最近使用时间、归档大小、来源提交和准备步骤摘要。下载缓存不纳入快照 LRU，继续沿用现有缓存生命周期。

## 日志

Agent 运行新增或扩展以下结构化事件：

- `workspace.snapshot.lookup`
- `workspace.snapshot.missed`
- `workspace.snapshot.restored`
- `workspace.snapshot.restore_failed`
- `workspace.snapshot.created`
- `workspace.snapshot.cancelled`
- `workspace.prepare.inherited`

手动预热状态仅用于仓库管理页面，日志经过 Secret 脱敏并受 `max_output_bytes` 限制。
