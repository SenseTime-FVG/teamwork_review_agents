# GitLab 活动与手动触发设计

## 目标

补齐 GitLab MR 的结构化活动读取，保留 GitHub 行为和现有规则；不读取评论正文，不由当前状态伪造一次提交或合并动作。

## 活动来源

- MR 详情的创建、关闭、合并时间；状态事件和标签事件。
- MR diff versions 的服务端版本时间和 Head SHA；初始版本及仅基线变化不算新提交。
- 审批、流水线、草稿和其他字段继续由快照差异检测。
- 各来源稳定 ID 加来源前缀，按平台时间、同源 ID 稳定排序；不能把 Git commit 的作者日期当推送时间。

## 游标及故障

- 保存各结构化来源的 ID 高水位、详情事件标记及最新可识别活动。
- 已有快照首次启用适配时只建立游标；新发现 MR 按现有首次回看窗口处理。
- 正常轮询只返回游标之后的活动，同一字段已由快照反映时跳过无变化动作。
- 分页完整读取并设安全上限，达到上限或任一来源失败时不推进成功游标；仍做快照检测，并保存可见的失败状态。
- 故障恢复后重新建立活动基线，以免把降级期间已由快照检测过的变化重新触发；故障期间发生后又撤销的瞬时变化不承诺补回。
- 游标和快照、事件事务化保存；重启、重复扫描、重复时间戳不重复入队。
- 详情 Head 与最新 diff version 不一致时降级；列表快照与活动读取时的 Head/状态不同则保留上次事务，等待下一轮扫描，不生成反向变化。

## 能力和手动触发

- 平台能力由适配器声明，接口不再硬编码只有 GitHub 支持。
- 最新平台事件保持真实来源，不混入系统快照事件；另提供手动触发候选。
- 有可靠平台活动时优先使用它；否则可重放该 MR 已记录的最近系统检测事件（不选手动事件、不跨 Provider、不选已经过期的源版本）。
- 系统重放保留原事件上下文和审计引用；仍交由现有规则处理。无候选时明确提示，不构造虚假业务事件。
- 页面区分等待扫描、暂无事件、活动读取失败，确认框注明平台活动/系统检测和事件时间。

## 边界

不修改部署配置或 Token，不自动启动真实 Agent，不发布远端评论，不重启服务。只读现场验证只使用目标仓库结构化端点。
