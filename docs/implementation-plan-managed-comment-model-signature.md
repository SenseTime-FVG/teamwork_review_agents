# 托管评论模型签名实施方案

## 配置与管理界面

- 为 `AgentConfig` 和前端 `Agent` 类型增加 `managed_comment_model_signature`，默认关闭并保持旧配置兼容。
- 在托管评论配置区增加独立开关；托管评论关闭时禁用操作但不清除已经保存的值。
- 更新配置示例和 README，说明签名来源、显示格式及 CI 评论不受影响。

## 服务端

- 在 Agent 托管评论发布入口根据可信 `run_id` 读取本轮 `model_snapshot`。
- 将模型与有效推理强度格式化为单行安全文本；缺少具体模型时使用明确的账号默认提示。
- 在调用通用托管评论服务前追加统一 Markdown 尾注，使签名参与长度限制、内容哈希、更新和重建逻辑。
- 不修改 Agent Prompt、`publish_comment` 工具参数和 Preflight 评论路径。

## 验证

- 验证配置默认值及显式启用值能正确加载。
- 验证明确模型与推理强度、无推理强度及缺少模型快照时的签名格式。
- 验证服务端使用当前运行快照并把签名写入远端评论；关闭开关时正文保持原样。
- 验证目标分支更新、源版本追加、远端删除重建和 60 KiB 限制不回归。
- 执行 Python 定向及全量测试、前端生产构建、编译检查和补丁检查；验证通过后生成规范提交并自动推送当前分支。
