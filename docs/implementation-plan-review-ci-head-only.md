# 审核 CI 源提交校验实施方案

1. 修改通用审核 Prompt：CI 与当前源提交关联即可；删除合并结果 CI 对当前目标提交的额外绑定和新鲜度校验，保留审核自身的目标 ref 漂移保护。
2. 明确本地及远端 CI 在审核前或审核中失败均立即终止；区分非必要检查失败、成功、运行中、未知和没有 CI，不放宽当前源提交校验。
3. 同步共享 CI 工具说明，避免运行时额外指令重新引入目标版本校验；GitLab 合并结果流水线使用固定项目 Commit API 校验源父提交，拒绝旧源和错误元数据，不检查目标父版本。等待器保持只读、固定期限和源提交保护。
4. 更新现行设计、实施说明和 README，说明成功不等于证明最新合并组合已经运行测试。
5. 增加仅审核、自动合并及默认模式的模板渲染回归，检查真实 Agent 输入同时保留新 CI 规则和既有门禁；通过平台替身覆盖目标变化后成功、失败优先级、旧源提交和只读请求。
6. 运行相关回归、后端完整测试和差异检查；仅提交本次相关文件，按项目规范提交并推送，保留无关未跟踪文件。
