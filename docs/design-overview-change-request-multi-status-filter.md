# 已扫描 MR / PR 多状态筛选设计

## 背景

运行概览中的“已扫描 MR / PR”目前只能按一个状态筛选。排查历史变更时，用户经常需要同时查看多个终态，例如“已关闭”和“已合并”，单选会增加重复切换成本。

## 目标

- “已扫描 MR / PR”的状态筛选支持同时选择“打开”“已关闭”“已合并”。
- “全部状态”与具体状态互斥。
- 保持最近变化事件的状态筛选为单选。
- 保持既有单个 `status` 查询参数兼容。

## 交互规则

1. 未选择具体状态时等同于“全部状态”。
2. 点击“全部状态”会清空所有具体状态。
3. 从“全部状态”切换到具体状态时，只选中被点击的状态。
4. 具体状态之间可以任意组合。
5. 取消最后一个具体状态后自动恢复为“全部状态”。
6. 下拉触发器在单选时显示状态名称，多选时使用顿号连接所选状态。

## 接口约定

前端通过重复查询参数表达多选：

```text
GET /api/change-requests?status=opened&status=merged
```

未提供 `status` 表示全部状态。原有 `status=merged` 仍然有效。

## 数据查询

状态集合非空时，快照列表与总数查询都使用 `IN` 条件，保证分页数据与总数一致。状态集合为空时不添加状态条件。

## 非目标

- 不改变最近变化事件的状态筛选方式。
- 不改变 MR / PR 状态枚举。
- 不改变扫描器保存快照的逻辑。
