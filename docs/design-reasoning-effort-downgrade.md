# 推理强度兼容降级设计

## 目标

外部 Provider、Agent、全局默认及回退模型支持选择 `xhigh`、`max`，不再提供 `minimal`。内置 Codex 仍优先使用模型能力目录，过滤 `minimal`；不把 UI 的候选档位视为上游支持证明。

## 请求处理

在 Teamwork 托管的模型循环中，只在上游明确拒绝 `reasoning.effort`、`reasoning_effort` 或整个 `reasoning` 参数时，按 `max → xhigh → high → medium → low → 不传 effort` 重试同一模型。已有 `ultra` 被拒绝时先降到 `max`；历史 `minimal` 或未知档位被拒绝时直接省略参数，不猜测其强度顺序。

通过协议客户端保留的结构化错误字段判断兼容性，不根据 HTTP 400 或笼统错误字符串触发降级。401、403、429、5xx、连接超时及其他参数错误保持既有错误处理。移除 effort 时一并省略当前仅为 effort 添加的 reasoning 对象，避免残留 summary 导致整个 reasoning 参数仍被拒绝。

降级发生在当前模型回合内部，沿用已经提交的对话历史，不重复执行工具，不新建工作区、不重启 Agent。成功档位在当前候选的后续回合继续使用；切换到另一候选时重新使用该候选自身配置。降级不写回配置、不建立跨运行缓存。无 effort 的请求仍失败时遵循现有错误分类和模型回退规则，不无限重试。

完整 Codex CLI 子进程模式不在本次自动降级范围内，其请求由 CLI 自己管理。

## 可观测性

保留脱敏的真实失败原因；单独记录 `model.reasoning_downgraded`，包含 Provider、模型、原始配置档位、失败档位、下一档位和错误原因。在消息时间线中显示中文降级提示，在运行详情显示配置档位、实际请求档位和降级轨迹。实际档位为空表示不传参数、交给上游默认，不表示已知上游最终使用的强度。

effort 降级与切换模型独立记录，不把同模型降级误报为 `fallback_used`。历史运行兼容缺失的新字段。

## 验收

- 完整降级链不包含 minimal，低档失败后只尝试一次无参数请求。
- 普通错误不误触发降级；上游脱敏原因可以查看。
- 多轮工具运行沿用降级档位，已完成工具不重复执行。
- 模型切换后使用新候选的 effort；配置值保持原样。
- UI 选项、中文提示及配置/实际档位展示一致。
