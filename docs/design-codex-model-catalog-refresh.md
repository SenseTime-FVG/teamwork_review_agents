# Codex 模型目录刷新设计

## 目标

Provider 下拉框跟随后台实际使用的 Codex CLI 与 CODEX_HOME，不能一直停留在旧版客户端写入的模型缓存。刷新目录不改变已保存或正在编辑的模型、Provider 和上下文窗口。

## 读取与降级

- 每次运行时目录请求使用已保存的 CLI/Home，通过同一个 App Server 读取 `config/read` 和分页 `model/list`，不创建模型会话、不执行推理。
- 根据 OpenAI Docs 的 `model/list` 协议请求可见模型，保留推理强度及快速模式能力。限制分页数量、总耗时并检测重复游标；中途失败不发布半份目录。
- 查询成功时以返回目录为准，包括空目录。查询失败才回退账号缓存，再回退 CLI 内置参考目录；展示查询错误、回退来源和查询时间。缓存不是账号实时可用性的保证。
- 只向前端输出白名单字段，不返回账号凭据、完整配置或 App Server 原始错误。

## 界面

- 初始加载、进入 Provider 页面和打开 Codex Provider 时刷新；提供只读模式也可用的“刷新模型”按钮。
- 刷新使用已保存配置，不读取编辑草稿。目录状态独立于表单，保留手工填写模型能力。
- 请求并发按配置版本合并；配置变化后的旧响应不得覆盖新目录。网络失败保留同一配置下的已有目录并明确提示，配置改变后不沿用旧 Home 的目录。
- 不在三秒状态轮询中查询模型目录。
