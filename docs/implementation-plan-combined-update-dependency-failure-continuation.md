# 组合更新中依赖失败后的文档续跑实施方案

## Prompt 调整

1. 将依赖阶段的 `FAILED` 与 `BLOCKED` 分开处理。
2. 为 `FAILED` 增加严格的阶段恢复流程，恢复成功后从原始合并后 SHA 继续文档任务。
3. 保留未知状态、协议校验失败、目标分支漂移和清理失败的整体终止行为。
4. 调整无更新判断、失败清理入口、最终输出字段和完成标准，使部分完成成为明确终态。

## 文档与测试

1. 更新 README 中组合 Runner 的行为说明。
2. 将设计和实施方案加入文档索引。
3. 增加 Prompt 契约断言，确保依赖 `FAILED` 可恢复续跑、`BLOCKED` 仍终止，并要求最终报告部分完成状态。

## 验收

- Prompt 不再包含 `FAILED` 与 `BLOCKED` 一并禁止文档 Agent 的旧规则。
- Prompt 明确要求恢复到原始合并后 SHA 后才可继续。
- 仅文档提交仍符合既有合法提交历史。
- 后端测试、Prompt 渲染测试与差异检查通过。
