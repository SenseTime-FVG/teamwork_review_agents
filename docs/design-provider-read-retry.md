# 平台只读请求退避与扫描时间窗口

GitHub / GitLab 的 GET 请求遇到连接中断、响应体断流或超时时，当前扫描立即失败。增加有限重试，降低短暂网络波动造成的扫描告警。

- 每个 GET 最多尝试三次，通常间隔一秒、两秒；支持 Retry-After 秒数或 HTTP 日期，单次等待最多三十秒。
- 重试网络传输错误、超时、远端协议断流，以及 HTTP 408、429、500、502、503、504。其他错误直接返回现有处理；可选接口的 403 / 404 仍返回默认值。JSON 格式错误不重试。
- 必须读取完整响应体才能返回数据；半截响应丢弃后重新请求。取消与外层超时立即生效。
- 日志记录 Provider、路径、错误类别、尝试次数与等待时长，不记录查询参数、认证头或响应正文。重试耗尽后继续按现有逻辑在 Dashboard 报错。
- POST、PUT、PATCH、DELETE 不加入自动重试。

仓库水位仍只在整仓扫描成功后持久化。假设成功水位为 t1，在 t2 失败，t3 再扫描时仍从 t1 回看，读取当时最新变化；不能把失败的 t2 当成新起点。

增量查询使用上次成功扫描的开始时间，额外保留现有两个扫描周期、至少六十秒的重叠。完成时间保留作页面展示，旧数据没有开始时间时回退到完成时间。这样耗时较长的扫描或退避期间发生的变化会在下轮继续覆盖，已入库事件依靠现有事务和事件标识去重。

平台分页并非原子时间快照：即时重试只重取失败的 GET，并不重放已经成功的整仓扫描；下一完整扫描从保留的水位开始。现有每仓最大条数配置继续生效。
