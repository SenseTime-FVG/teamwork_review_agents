# 依赖缓存清理实施方案

1. 增加共享/独占缓存使用锁及原子最近使用元数据，接入 Agent、两种 Preflight 和工作区预热，保持同仓库并行使用能力。
2. 实现有界缓存扫描、旧缓存保护期、活动任务保护及持锁复核删除，接入既有定时计划和维护保护；未知归属、权限错误、取消与配置变化须可见。
3. 增加独立闲置保留天数配置，更新清理卡片、兼容旧结果，并同步示例配置、README、设计和文档索引。
4. 以临时目录覆盖跨进程锁、活动任务、最近使用时间、损坏元数据、路径链接、过期删除及调度展示；所有自动化测试不得操作真实 `data`。
5. 运行相关回归、完整后端测试、前端测试和构建，记录验证结果，审查完整差异后仅提交并推送本次任务变更；不自行重启服务。

## 验证结果

- 后端完整测试：1579 项通过、10 项跳过，另有 2 条既有依赖弃用告警。缓存专项 31 项通过；覆盖原有工作区、CI、预热及快照的相关回归也通过。
- 前端测试：98 项通过；TypeScript 与 Vite 构建成功，保留现有单文件包超过 500 kB 的体积提示。构建资源的 JavaScript 语法及 HTML 引用检查通过。
- Python 编译与 `git diff --check` 通过。自动化删除验证仅使用临时目录；生产存量清理仅执行用户授权且已核验的 8 个过期工作区和 2 个旧缓存目录。
- `data` 实占从约 14 GiB 降至 7.5 GiB，约回收 6.3 GiB；数据库、凭据、未到期目录和归属不明的旧目录保留。未启动或重启后台，自动逻辑下次启动后生效。
