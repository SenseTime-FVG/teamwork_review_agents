# 模型上游事件后回退设计

## 背景

模型基座通过流式事件接收上游响应。上游可能先发送 `response.created`、文本增量或函数调用内容，再以 `server_error`、服务过载或连接异常结束。原实现把“本轮已经收到任意模型事件”作为禁止回退的条件，导致这类临时故障不会继续尝试已配置的备用 Provider，而是直接结束本次 Agent 运行并交给外层整体重试。

在当前模型工具循环中，流式事件只用于续期、展示和组装响应。只有 `create_response` 返回完整响应后，函数调用才会进入本地工具执行阶段。因此，上游在完整响应形成前失败时，丢弃本轮不完整响应并使用相同历史请求备用 Provider，不会重复执行工具。

## 设计

模型回退只依据错误是否可回退以及是否存在下一个可用候选。上游临时不可用、连接失败、超时、限流和可恢复的鉴权错误继续进入回退链；请求参数、上下文长度、工具结构和响应格式等确定性错误保持失败，避免把相同无效请求发送给所有 Provider。

回退沿用当前已经提交的对话历史。上一轮已经完成的工具调用及其结果都在历史中，备用 Provider 从当前失败回合继续生成，不会重新执行这些工具。当前失败回合的流式片段没有写入历史，因此不会污染备用请求。

`fallback_used` 只表示运行器已经成功切换到另一个候选。单个候选失败、候选不可用或回退链耗尽时，该字段不能因为存在失败记录而变为 `true`。实际切换继续产生 `model.fallback` 日志，供运行详情展示和诊断。

## 验收标准

- 模型已发送流式事件后发生可回退错误时，运行器继续尝试下一个可用候选。
- 已完成的工具调用不因模型切换而重复执行。
- 确定性请求错误仍然直接失败。
- 只有实际发生候选切换时，模型快照中的 `fallback_used` 才为 `true`。
- 实际切换时存在 `model.fallback` 日志。
