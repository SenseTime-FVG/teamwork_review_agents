# 请求级模型回退与运行内额度跳过

## 目标

内嵌模型工具循环每次发起新一轮模型请求时，重新从配置的主模型开始尝试。上一轮 A 临时失败后由 B 返回工具调用，不代表下一轮继续固定使用 B；工具执行完毕后仍先尝试 A。

明确额度耗尽是例外：候选以 `(Provider ID, 模型 ID)` 为身份，本次 Agent 运行中跳过该候选。不会禁用整个 Provider、修改配置、跨运行缓存或连带跳过其他模型。新一次运行重新检查全部候选。

## 错误分类

共享分类器只识别上游错误 `code` / `type` 的明确额度、余额或消费上限标识，包括 `insufficient_quota`、`credit_balance_exhausted`、`usage_limit_reached` 等。HTTP 429/402、模糊错误文本、`rate_limit_exceeded`、`slow_down` 本身不构成额度耗尽证据。

HTTP、Codex SSE 和兼容 JSON 错误都将分类结果保留到类型化异常；明确额度耗尽可进入模型回退，不在同一个客户端内重复尝试。参数无效、上下文超限等现有非回退错误策略不变。

参考：[OpenAI 错误说明](https://developers.openai.com/api/docs/guides/error-codes#api-errors)。该文档区分普通请求限流和额度、余额、消费上限错误；不能以 HTTP 429 直接判断余额不足。

## 循环与状态

- 请求之间重新选择候选，请求内部只向后回退，不循环重试 A。
- 运行内保留额度耗尽集合和各候选已发现的 effort 兼容降级，避免每轮重复发送已拒绝的 effort。
- 不清空历史，不重新执行工具，不把失败响应中的未完成调用加入历史。
- `model.request_started` 记录请求轮次与实际首选；`model.quota_exhausted` 解释本次运行内跳过；原有回退和失败事件保留。
- 快照记录实际当前模型、请求轮次、额度跳过名单和尝试轨迹；不记录凭据或完整上游响应。
- 不修改外层事件重试、上下文压缩或不透明的完整 Codex CLI 子进程内部调度。

## 验收

覆盖瞬时错误后恢复 A、额度耗尽跳过 A、B 瞬时错误不被长期跳过、跨运行恢复、候选身份隔离、全部失败有界终止、历史及工具结果不重放、effort 降级保持、协议错误分类和日志脱敏。
