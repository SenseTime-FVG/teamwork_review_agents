# GitHub 本地 CI 日志实施计划

1. 扩展 GitHub 评论适配器，读取并校验原生评论永久链接。
2. 复用完整日志导出与脱敏，默认把完整日志内嵌主评论；仅超出总长度上限时发布续页，目录放在主评论内。
3. 将 GitHub 接入现有后台发布队列，先回写终态、后补平台链接；移除 GitHub 状态中的管理后台 URL。
4. 在执行尝试记录中保存有界的合并材料，主评论锁内同时拼接诊断与日志；合并成功后清理同次旧版多余日志和目录评论。
5. 验证普通日志只有一条评论、晚到诊断仍更新同条、超长日志续页、失败恢复、清理保护、终态顺序和 GitLab 回归。
6. 必要验证通过后提交、推送，并重启后台确认健康。

## 长度边界与诊断完成后的重排

- 统一 GitHub 合并与含日志正文的 60 KiB 上限，验证 54～60 KiB 的真实边界，不因普通摘要预算误拆评论。
- 诊断完成后刷新独立日志队列，按实际报告重排并清理不再必要的续页；复用指纹覆盖诊断材料与排版版本。
- 队列任务按领取版本提交终态，覆盖诊断在旧任务执行期间完成的竞态，保留每个版本的有限重试。
- 验证边界正文、完整诊断保留、迟到诊断自动合并、刷新不丢失、旧数据库兼容以及 GitLab 回归。
