# 运行概览统一仓库筛选设计

## 目标与交互

在“运行概览”标题旁增加仓库选择器，默认“全部仓库”。选项显示仓库名称，查询使用稳定的仓库 ID；停用但仍在配置中的仓库也可查看历史记录。

- MR / PR、变化事件、Agent 运行统计与两个列表统一跟随顶部仓库选择。
- 列表移除重复的仓库筛选，保留各自状态、编号和每页条数设置。
- 切换仓库时回到第一页，清空批量勾选、未提交的操作确认与详情抽屉。
- 新范围数据到达前显示加载提示，不将旧仓库的数据放在新仓库标题下；过期响应不得覆盖新选择。
- 单仓库显示最近成功扫描时间；无扫描水位时显示“暂无记录”。全部仓库保留全局最近扫描展示。

## 数据与边界

`GET /api/status` 增加可选 `repository_id`，不传或为空时保持全局统计。传入时对事件、快照和运行做仓库级统计，运行兼容旧数据通过关联事件或资源键确定归属。统计不受列表状态、分页或编号限制。

响应增加查询范围与仓库最近成功扫描时间，来自现有 `repository_scan:<id>` 水位，不增加数据库表，也不触发扫描。

后台调度器、错误提示、立即扫描、暂停/恢复仍是全局服务能力，界面明确标注“全局”。筛选不改变配置、调度逻辑、运行与日志页的独立筛选或远端数据。

## 安全与兼容

沿用现有管理 API 认证；只返回安全统计及扫描完成时间，不暴露仓库环境变量或凭据。查询使用绑定参数，历史资源键匹配转义 SQL 通配符。未知仓库返回空统计和空扫描时间，不回退成全局数据。
