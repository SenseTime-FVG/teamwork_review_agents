# 沙盒进程标记读取竞态修复设计

## 问题与范围

GitHub Actions 运行 `38018497886` 的 macOS 检查在
`test_bridge_descendants_stop_with_tool[cancel-with-read-contention]` 失败：
模拟拒绝读取的次数为 `0`，而测试要求 `2`。失败发生在取消命令和进程退出校验之前，
并不能据此判定运行时的进程清理失败。

模拟函数先检查 `Path.exists()`，再执行真实读取。子进程通过原子替换发布 PID 标记，
若发布发生在这两步之间，存在性检查返回假而读取成功，模拟冲突即被绕过。

## 修复方案

- 删除模拟函数中的存在性预检查；先真实读取，成功后才注入前两次模拟拒绝。
- 真实文件不存在或真实读取异常继续传播，不消耗模拟拒绝次数。
- 保留原有超时、取消、两次模拟拒绝以及父子进程退出的全部断言和时限。
- 增加确定性发布竞态场景：让目标文件的存在性检查持续返回假，真实读取仍读取
  子进程发布的 PID 文件，验证模拟拒绝不能依赖单独的存在性检查。

## 非目标

不修改运行时进程管理、不放宽断言、不修改平台工作流，也不触发真实模型调用。

## 验证

先在旧读取逻辑上运行新增场景，确认以拒绝次数 `0 != 2` 失败；修复后运行
全部标记场景、重复竞态场景、相关进程测试及完整套件。推送后检查三平台 CI。
