# 实施方案

## 阶段一：项目骨架与配置

- 建立 Python 包、命令行入口和示例配置。
- 使用 Pydantic 校验 Provider、仓库、Agent 与规则引用关系。
- 所有相对路径以配置文件所在目录为基准解析。

验收：配置错误能在启动阶段给出明确提示；示例配置可以通过 `validate`。

## 阶段二：扫描与事件

- 实现 GitHub/GitLab API Adapter。
- 规范化变更请求快照。
- 实现快照差异检测和稳定事件 ID。
- 通过 SQLite 事务同时保存快照和事件。

验收：相同快照重复扫描不会重复产生事件；字段变化会生成对应事件。

## 阶段三：规则与运行器

- 实现规则条件操作符。
- 实现事件和 Agent 运行幂等。
- 实现 SQLite 资源租约与续期。
- 使用 `codex exec --json --ephemeral` 执行 Agent 并解析最终消息。

验收：读 Agent 可并行；同一资源上的写 Agent 串行；超时和非零退出码能正确记录。

## 阶段四：Sub-agent MCP

- 提供 STDIO MCP Server。
- 实现 `invoke_agent` 工具。
- 校验调用白名单、递归深度和根任务总调用次数。
- 将父子运行关系和同一根任务 ID 写入审计记录。

验收：允许的 Agent 可以被调用；越权、超深和超量调用会被拒绝。

## 阶段五：验证与交付

- 为事件检测、规则匹配、锁和 sub-agent 策略编写测试。
- 提供 `scan-once --dry-run`，便于在不启动 Agent 时验证 Provider 与规则。
- 完善 README、示例提示词与故障日志。

验收：测试通过；CLI 帮助和配置校验可运行；无真实 Token 时也能完成离线单元测试。

## 阶段六：分层环境与 Prompt 模板

- 增加全局、仓库和 Agent 环境变量。
- 支持字面值、宿主机环境引用、Secret 与进程/Prompt 暴露策略。
- 实现 `${{ENV_NAME}}` 渲染、缺失变量空字符串和运行变量注入。
- 在日志、Prompt 快照和 Agent 结果落库前统一脱敏。

验收：覆盖优先级正确；缺失变量为空；Secret 默认不进入 Prompt 或日志。

## 阶段七：后台 API 与热加载

- 增加 FastAPI 服务与服务生命周期管理。
- 增加配置读取、校验、原子保存、版本记录和文件热加载。
- 增加立即扫描、暂停、恢复、健康检查和状态接口。
- 增加可选管理员 Token 认证。

验收：UI 保存无效配置不会破坏当前运行；有效配置在下一任务生效；后台可长期运行。

## 阶段八：实时日志与管理 UI

- 将 Codex JSONL 与 stderr 改为流式读取和逐条持久化。
- 增加日志游标查询与 SSE。
- 实现 React 仪表盘、仓库、环境变量、Agent、规则和运行页面。
- 构建静态资源并由 FastAPI 同源提供。

验收：运行中可实时看到日志；刷新后可继续查看历史；UI 能完成全部配置编辑。

## 阶段九：本地服务进程管理

- 增加 `run` 前台运行命令，并保留 `serve` 兼容入口。
- 增加 `start` 后台启动、`stop` / `end` 停止和 `restart` 重启命令。
- 使用配置专属 PID 文件和进程锁阻止重复启动。
- 后台进程继承启动环境，将控制台输出写入 `data/` 日志。
- 停止时校验 PID 与进程启动时间，优雅退出超时后再强制结束。

验收：后台启动后终端可以退出；重复启动不会产生第二个实例；停止和重启能正确管理对应配置的服务进程。

## 阶段十：已扫描 MR / PR 可见性与事件补发

- 在状态存储中增加快照列表、快照状态统计和独立事件入队能力。
- 增加已扫描 MR / PR 查询接口，以及对单个快照补发 `change_request.discovered` 的幂等接口。
- 在概览中分别展示快照数量与变化事件数量，并增加已扫描 MR / PR 列表。
- 补发前展示影响确认；补发后唤醒后台按当前规则调度，已补发项目禁用重复操作。

验收：首次只建立基线的 MR / PR 能在概览中看到；补发操作只产生一条稳定事件；重复补发不重复入队；没有匹配规则时不启动 Agent。

## 阶段十一：规则多选交互

- 将触发事件、触发 Agent 和限制仓库从原生多选框改为复选框列表。
- 支持直接点击切换多个选项，并显示当前已选数量。
- 保持配置结构与后端规则匹配逻辑不变。

验收：无需按住 `Command/Ctrl` 即可连续选择多个事件、Agent 或仓库；取消选项与保存后回显正确。

## 阶段十二：重复变化、规则级单轮去重与 MR 输入契约

- 将远端更新时间纳入事件 ID，允许相同状态转换在不同时间重复产生事件，同时保持重复扫描幂等。
- 为事件记录增加扫描批次标识，并按同一批次、仓库和 MR / PR 编排规则任务。
- 为规则增加 `deduplicate_per_scan`；启用后把同一批次中匹配的动作合并，并让每个目标 Agent 只运行一次。
- 将 Codex Prompt 的动态上下文收敛为 `mr` 对象和 `mr.action` 数组，不传递新旧快照、变化字段或内部匹配字段。
- sub-agent 只继承仓库上下文，不自动接收 `mr` 与动作数组；父 Agent 通过 `invoke_agent` 指定目标、`task` 和可选补充上下文，并自行决定是否传递 MR 信息。
- 在 UI、示例配置和 README 中解释去重边界及轮询无法恢复未观察中间状态的限制。

验收：同一 PR 的两次独立 reopen 被扫描器观察后产生不同事件；同一快照重复扫描不重复入队；规则去重关闭时多个事件分别运行，开启时同一规则和 Agent 只运行一次且 `mr.action` 包含全部匹配动作；sub-agent 的任务由父 Agent 指定，默认 Prompt 不包含根 Agent 的 MR 数据。

## 阶段十三：规则级 sub-agent 工作区继承

- 为规则增加 `inherit_workspace`，默认关闭，并在根 Agent 的 MCP 调用上下文中携带该策略和当前绝对工作目录。
- 开启时让整条 sub-agent 调用链复用当前工作目录，使父 Agent 的当前分支、暂存区和未提交文件对子 Agent 可见。
- 关闭时为 sub-agent 创建基于 MR / PR Head 的独立 detached Git worktree，并保留有修改的工作目录供审计和后续处理。
- 对共享工作区的 sub-agent 委托串行化，同时沿用根运行 ID 的可重入工作区锁。
- 在 UI、示例配置和 README 中说明该选项只继承文件系统与 Git 状态，不自动继承 MR / PR 输入或父 Agent 对话。

验收：默认 sub-agent 的工作目录与父 Agent 不同且指向 MR / PR Head；开启规则选项后父子 Agent 的工作目录完全相同，父 Agent 的当前分支和未提交文件可见；嵌套 sub-agent 延续同一策略；同一父 Agent 的共享工作区委托不会并发写入。

## 阶段十四：Agent 工作区说明与长名称编辑

- 在 Agent 页面说明根 Agent 的工作目录由触发仓库决定，而不是 Agent 自身绑定。
- 说明同一仓库只读运行可并发、声明本地仓库写操作的运行按工作目录串行。
- 扩展 Agent 名称编辑区，使较长名称无需横向滚动或频繁移动光标即可查看和修改。

验收：Agent 页面无需查阅外部文档即可理解工作区来源与并发边界；常见长 Agent 名称能在桌面宽度下完整显示。

## 阶段十五：每次 Agent 运行独立 worktree

- 将仓库配置目录收敛为基础 Git 仓库，每次根 Agent 和未继承父目录的 sub-agent 按运行 ID 创建独立 detached worktree。
- 将本地写锁从物理工作目录调整为仓库与 MR 源分支，保证同一分支写入串行、不同分支并行。
- 开启规则工作区继承时，让 sub-agent 复用父 Agent 本次运行的临时 worktree；继承者不负责删除父工作区。
- 成功且无本地遗留或提交已推送时立即删除；失败、脏文件和未推送提交保留，并按 `worktree_retention_days` 延迟清理。
- 在仓库根目录忽略默认数据目录下的 `/data/worktrees/`，防止运行 worktree 和保留标记进入版本控制，但不以 Git 忽略代替生命周期清理。
- 在 Agent 页面、仓库页面和运行详情展示基础仓库、临时工作区、并发边界及清理状态。
- 为 worktree 创建、隔离、继承、分支锁、立即清理和保留状态补充测试。

验收：同仓库不同 MR/分支的根 Agent 工作目录不同并可并发；同一源分支的写 Agent 仍串行；继承 sub-agent 与父 Agent 路径一致；无修改运行结束后 worktree 被删除；脏或未推送工作区被保留并可在 UI 中识别。

## 阶段十六：SKILL 管理与 Agent 独立装载

- 增加顶层 `skills` 配置、Skill 目录与 `SKILL.md` 元数据校验，并校验 Agent 的技能引用。
- 增加受管 `./skills/` 目录、文件夹导入接口、路径安全限制和已有 Skill 列表接口。
- 在每次 Codex CLI 运行的临时 worktree 中投影已配置技能，并按当前 Agent 显式启用或禁用应用管理的技能；运行结束后清理投影。
- 增加 SKILL 管理页面，并在 Agent 页面为每个 Agent 提供独立多选。
- 明确 sub-agent 使用自身技能配置，`inherit_workspace` 不改变技能选择。
- 更新示例配置、README、后端测试和前端构建产物。

验收：合法 Skill 文件夹可从 UI 导入并显示元数据；非法或越界目录被拒绝；Agent 只能引用已配置 Skill；不同 Agent 在同一工作区运行时各自只启用所选的应用 Skill；sub-agent 不继承父 Agent 的技能列表；运行完成后业务仓库不残留 Skill 投影文件。

## 阶段十七：GitHub Timeline 增量事件与快照对账

- 增加统一的 Provider 活动模型与活动批次，保留平台稳定 ID、动作类型、发生时间和最小必要数据。
- 为 Provider 增加可选的单 MR / PR 活动读取接口；GitHub 实现 Issue Timeline 分页与重叠游标，GitLab 暂时回退快照差异。
- 在 SQLite 中按 Provider、仓库和编号持久化不透明活动游标，并与快照和事件原子提交。
- 每轮候选筛选前为已有快照补齐 Timeline 基线；首次启用时不重放历史，游标丢失时安全重置基线，并继续用快照差异对账。
- 将 `closed`、`reopened`、`merged`、`committed`、`head_ref_force_pushed`、Draft 和标签活动转换为现有语义事件，并为每个动作配套生成 `updated`。
- 活动事件保留发生时的旧、新快照，同时携带本轮最终快照；规则匹配使用事件快照，Agent 输入、环境、工作区和锁使用最终快照。
- 活动应用后的中间快照继续与最终详情比较，只补充 Timeline 未覆盖的审批、流水线、可合并状态和元数据变化，避免重复事件。
- 增加 Provider 分页游标、首次基线、同周期 `open -> closed -> open`、新增 commit、游标重试和状态存储原子性的测试。
- 更新 README，说明 PR API、Timeline、快照和未来 Webhook 的职责边界。

验收：关闭并在下一轮扫描前重新打开仍产生按顺序排列的 `closed`、`updated`、`reopened`、`updated`；新增 commit 产生稳定且可重试的 `commits_changed`；重复读取相同 Timeline 游标不重复入队；审批和流水线等非 Timeline 字段仍由快照差异产生；首次升级不会自动重放历史事件。

## 阶段十八：扩展通用代码审核标准

- 增加改动范围和爆炸半径检查，要求评估变更与 MR / PR 目标的关系、共享组件的其他消费者以及回归与回滚边界。
- 增加仓库卫生检查，识别意外提交的运行、调试、缓存、临时、生成产物和大型二进制，同时允许项目明确需要版本化的 fixture 与产物。
- 增加路径可移植性检查，覆盖开发机绝对路径、当前工作目录假设、易变层级和临时路径的耐久性误用，但不绝对禁止合理的相对路径或系统路径。
- 增加配置命名与归属检查，要求与仓库现有命名空间、组件作用域、第三方命名和兼容策略保持一致。
- 明确新检查不自带阻塞等级，问题仍统一按通用 Prompt 的证据充分性、变更归因、现实可达性、实质影响和可恢复性判定。
- 不引入 AI、Agent、Workflow 或 aGen 的专属架构规则。

验收：通用 Prompt 能明确引导审核者检查上述四类问题；不会仅因改动较广、未拆分、路径或命名风格就阻塞合并；不含 aGen 的目录、变量前缀、Workflow 入口、Agent 工具或 Router 契约等项目专属要求。

## 阶段十九：Codex CLI 运行时默认配置

- 增加 `runtime.codex` 配置模型，覆盖默认模型、推理强度、快速模式、输出详细度、交互风格、联网搜索和受限高级配置。
- 为 Agent 增加对应的可选覆盖项；未填写时继承运行时默认，sub-agent 使用目标 Agent 自己的覆盖项。
- 将运行时与 Agent 参数转换为逐次 `codex exec --config` 参数，并保证 Agent 覆盖运行时、应用托管 MCP 与 Skill 参数不受高级配置影响。
- 移除强制忽略用户 Codex 配置的启动参数，使未覆盖项继续遵循 Codex 原生配置层级。
- 增加本机模型目录与模型来源检查接口；读取失败时提供安全回退，不把不确定的 CLI 内置模型显示成确定值。
- 增加“运行时配置”页面，并在 Agent 页面显示具体继承来源、模型候选和对应覆盖控件。
- 更新完整配置示例、README、后端测试和前端构建产物。

验收：运行时默认参数进入每次 Codex 命令；Agent 显式值覆盖全局运行时；sub-agent 不继承父 Agent 覆盖；高级配置不能覆盖应用安全边界；模型目录不可用时仍可编辑和运行；UI 能区分 Teamwork 默认、用户配置和 CLI/账号决定三种模型来源。

## 阶段二十：固化内置 Agent、规则模板与 Prompt

- 将当前通用审核、增量文档入口和增量文档更新三个 Agent 写入 `config_example.yaml`，保留 sub-agent 白名单、环境变量与写作用域。
- 将通用审核与增量文档更新两条规则写为可直接编辑的内置模板，并统一设置 `enabled: false`。
- 通过 `.gitignore` 精确放行三个内置 Prompt，其余 `prompts/` 内容继续忽略。
- 更新 README 与示例说明，明确内置 Agent 不等于自动运行，启用规则才会触发。
- 增加示例配置测试，校验内置 Agent、规则禁用状态、Prompt 文件存在和 sub-agent 引用关系。

验收：复制示例配置后可以在 UI 中看到三个内置 Agent 和两条禁用规则；未主动启用规则时不会触发 Agent；示例配置不包含 Provider、仓库或真实 Token；三个内置 Prompt 可被 Git 跟踪，其他本地 Prompt 仍被忽略。

## 阶段二十一：分离事件处理与 Agent 运行状态

- 增加事件到 Agent 调度的持久化关联表，使用 Agent 幂等键关联后续运行记录，并支持一次去重运行对应多个事件。
- 规则规划完成后立即把无匹配事件标记为 `unmatched`，有匹配事件标记为 `triggered`，不再让无关事件等待同批次 Agent。
- Agent 运行记录先进入 `queued`，实际开始 Codex CLI 前切换为 `running`，并兼容异常退出恢复与幂等判断。
- 在最近事件接口中聚合触发总数及排队、执行、成功、失败、超时数量。
- 在运行概览中分开展示事件状态和 Agent 进度，明确“未触发”“Agent 排队中”“Agent 执行中”等语义。
- 补充状态存储、编排、API 与 UI 测试，并重新构建静态资源。

验收：未被规则选择的 `updated` 事件在一次调度后显示“未触发”，不会跟随同批次其他 Agent 保持处理中；匹配事件可展示关联 Agent 总数与实时进度；等待资源锁时为排队中，Codex CLI 启动后才为执行中；规则去重时所有被合并事件都能关联到同一次运行。

## 阶段二十二：设计、历史变更与目标分支一致性审核

- 在首次工具操作中同时读取 `REVIEW_SKILLS`、`REVIEW_DESIGN_DOC_DIR` 和 `REVIEW_CHANGE_HISTORY_DIR`，将后两者定义为仓库内单目录配置。
- 非空目录配置无效时发布配置错误评论并阻止合并，不回退自动扫描；空值时扫描仓库中可能的设计和历史 change 目录，未找到时继续审核。
- 从本次 diff 设计文档、MR / PR 描述、代码、测试和配置中建立当前功能意图，扫描文档目录后完整读取所有命中的相关文档及必要引用。
- 检查当前功能与有效设计、领域不变量、对外契约、已有功能和历史变更决策是否存在无法同时成立的未解决冲突。
- 同时锁定 `REVIEW_HEAD_SHA` 与 `REVIEW_TARGET_SHA`，以 merge base `O`、目标基准 `T`、源分支 `H` 和拟合并结果 `M` 建立四版本一致性审核。
- 审核 `O → T`、`O → H` 与 `T → M`，对文件、代码块、符号、控制流、契约、schema、配置、路由、注册项和测试的重叠变更进行语义检查，不仅依赖 Git 文本冲突。
- 将意外覆盖、回退、破坏目标分支功能或与设计和历史决策存在的已确认未解决冲突列为阻塞问题；有完整替代、兼容、迁移、回滚和测试证据的正常演进不误判为冲突。
- 任一基准 SHA 变化时立即结束，不评论、不切换到新基准继续审核、不合并。

验收：环境变量非空时只使用指定单目录，为空时能发现相关目录；无文档目录的仓库可继续审核；无效显式目录阻止合并；审核结论能用本次变更、既有文档或目标分支代码证据证明一致或冲突；目标分支 SHA 在审核期间变化时无评论结束；不因仅修改同一文件或符号就判定冲突。

验收：端口已由旧服务占用时新进程即使写入过 PID 文件也不能显示启动成功；运行中移走 PID 和锁文件后 `stop` 仍能找到并结束原进程；`restart` 返回成功时旧 PID 必须不存在且健康接口必须返回新 PID；不同配置或其他程序占用端口时不会被误杀。

## 阶段一百零二：基础设施异常停止写回 PR 失败结论

- 明确区分代码门禁结论与 Teamwork 基础设施异常：`success`、`failure` 和 `timed_out` 保持既有平台状态语义，`error` 继续在事件与 Preflight 运行中记录并按事件重试额度重试。
- Preflight 结果为 `error` 时不发布远端终态 Commit Status，不创建、更新或删除托管失败评论，避免把 Git、网络、权限、进程启动或工作区清理故障表达成 PR 代码失败。
- 保留精确工作区准备成功后才发布 `pending` 的顺序，使准备阶段的 Git 与权限异常不会在远端遗留运行中状态；真实终态的状态写回失败仍只补发已有结论，不重复执行 CI 命令。
- 基础设施异常不得覆盖同一源代次此前真实的失败评论；后续真实成功仍按既有生命周期删除当前代次的失败评论，命令失败和超时继续创建或更新评论。
- 补充基础设施异常无远端状态、无评论写回且保持可重试的回归测试，并保留失败、超时、成功、缓存复用、状态补发和评论脱敏测试。
- 执行 Preflight 定向测试、Python 全量测试、编译与补丁检查；不启动、停止或重启用户服务，验证通过后自动提交并推送当前分支。

验收：Git 操作、网络、权限或进程启动异常只在 Teamwork 内显示“本地 CI 异常”并进入既有重试，不再在 GitHub PR 上创建“本地 CI 未通过”评论或红色 Commit Status；真实 CI 命令失败和超时仍能阻断门禁并同步远端，成功结果与失败评论清理不回归。

## 阶段一百零三：手动事件重新执行已耗尽的基础设施异常

- 保持相同仓库、PR、Head SHA 和配置版本的成功、命令失败与超时结果复用语义；普通扫描事件遇到已耗尽尝试次数的基础设施异常时继续复用终态，防止自动无限重跑。
- 手动事件遇到同一幂等键下已耗尽尝试次数的 `error` 时，在一个 SQLite 即时事务内归档旧运行的活动幂等键，并创建新 `run_id`、新步骤快照和完整重试额度。
- 旧 Preflight 运行、日志、步骤和原事件关联必须保持可追溯；新手动事件关联新运行并显示“本批次新执行”，不能继续显示“复用历史结果”。
- 新运行继续占用原活动幂等键，因此完成后自动成为后续相同 Head 与配置的可复用结果；并发触发只能有一条新运行获得活动键，其他请求复用该运行，禁止重复执行。
- 更新手动触发确认说明，明确常规 CI 结果可能复用，但已耗尽的基础设施异常会重新运行；不把事件重放普遍改成强制重跑 CI。
- 补充状态层原子换代、旧运行保留、新运行关联、执行器错误后手动成功和普通扫描不越过上限的回归测试；执行 Python 定向及全量测试、前端生产构建、编译和补丁检查，验证通过后自动提交并推送当前分支。

验收：基础设施故障恢复后，管理员再次手动触发历史事件会真实创建并执行新的 Preflight，而不是复用已耗尽的异常记录；旧运行仍可查看，新运行拥有独立 ID 和完整重试次数，成功后可继续启动要求 CI 的 Agent；自动扫描、真实 CI 终态复用、远端状态与评论语义不回归。

## 阶段一百零四：Preflight 失败评论刷新与全代次清理

- 在状态层增加按仓库、MR / PR、命名空间和槽位读取全部托管评论映射的能力，保留现有按源版本代次读写接口和 Agent 评论行为。
- 在托管评论服务增加槽位级资源租约：真实 Preflight 失败先删除该槽位全部历史远端评论与映射，再在时间线底部创建并保存当前失败评论；删除未完成时不创建重复评论。
- 区分新执行与缓存复用：缓存复用失败或超时时保留现有活动评论，仅在映射缺失时补建；当前最新源版本的缓存复用成功与新执行成功都清理该槽位全部失败评论，历史旧代次成功不误删新 Head 的失败评论。
- 保持 `error`、`superseded` 和手动无编号 CI 不触碰评论；远端删除或创建失败继续只记录脱敏日志，不覆盖 Commit Status 或真实 CI 终态。
- 更新失败评论说明、README、Preflight 指南和累积设计，明确 Preflight 只保留一条活动失败评论，Agent 评论仍按源版本代次保留审核历史。
- 补充真实连续失败旋转、缓存复用不旋转、历史代次成功清理、远端异常隔离和 Agent 评论不回归测试；执行定向与 Python 全量测试、编译和补丁检查，不启动、停止或重启用户服务，验证通过后自动提交并推送当前分支。

验收：每次新执行失败后，PR / MR 时间线底部只有一条最新 Preflight 失败评论；同一 CI 结果被多个事件复用时评论不反复删除或创建；最新结果通过后所有历史代次失败评论均被清理；Agent 托管评论的历史代次语义保持不变。

## 阶段一百一十：Agent 基模分级回退策略

- 在全局运行配置增加有序的默认模型回退链，在 Agent 配置增加可选的 Agent 级回退链；Agent 显式主模型的有效顺序为“Agent 主模型 → Agent 回退链 → 全局默认模型 → 全局回退链”，未显式指定主模型时仍以全局默认模型为第一节点。
- 所有候选使用 `(Provider, Model)` 身份去重并保留首次出现位置，兼容 Provider 默认模型；停用或不可用的 Provider 跳过，不改变现有 Codex CLI 默认基座模式和 Agent 模型显示的具体值。

验收：全局 `A → B → C` 且 Agent 指定 `D` 并配置 `E → F` 时，实际顺序严格为 `D → E → F → A → B → C`；重复节点只调用一次。模型 Provider 发生可回退故障时能在同一运行中逐级切换并显示最终模型与完整脱敏轨迹，非模型错误不会误触发回退，既有 Codex CLI、事件、评论、CI 与运行记录语义不回归。
