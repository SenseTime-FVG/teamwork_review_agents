# Codex CLI 版本探测退避设计

## 目标与边界

运行中的 CLI 升级可能短暂导致 `codex --version` 超时、非零退出或安装文件不可执行。仅在当前模型请求前重试版本探测，保留对话、工具结果和已完成操作，不重跑 Agent，也不切换备用模型。

- 最多探测 6 次，包含首次；间隔依次为 10、20、40、80、120 秒，累计等待 270 秒。
- 单次探测仍最多 3 秒，在线程中执行，不阻塞事件循环。整个探测与退避窗口最多 300 秒，避免异常回调或调度延迟无限延长等待。
- 明确权限拒绝、版本不匹配及从未找到的配置命令立即失败；本轮已绑定程序升级时暂时缺失、非零退出、超时或无有效版本输出允许有限重试。
- 使用本轮固定的可执行文件路径，不改 PATH、不更新 CLI、不使用旧版本或 `unknown`。恢复后继续当前请求，同一请求的网络和 OAuth 重试仍共享有效版本快照。
- 耗尽时保留 `codex_version_probe_failed`，停止整轮自动重试，防止重放写操作。

## 等待与可观测性

版本探测和退避属于有固定期限的运行环境等待，不冒充模型输出或工具进展。只在该窗口内暂停当前 Agent 的普通无进展计时，不影响人工取消、父任务停止或子 Agent 总时限；退出后恢复原有计时。

独立运行诊断回调记录失败次数、下次探测次数、等待秒数和预计时间；恢复时记录成功次数和版本。正常请求和摘要请求都记录诊断，不把本地事件混入上游 SSE。消息页显示重试说明和当前倒计时，不每秒写日志；终态或后续事件到达后移除等待提示。日志不保存原始 stdout/stderr、环境变量、请求头或凭据。

## 验证

覆盖精确退避序列、短暂失败后恢复、耗尽不请求上游、不触发模型回退、之前的工具不重放、权限和配置错误快速失败、绑定路径不变、探测线程不阻塞、等待可取消、普通 idle 暂停且有界、子任务总时限保留、摘要诊断及前端倒计时。

部署需重启后台加载代码，已运行旧任务不热切换。本次不重启服务或重跑失败历史任务。
