# 托管模型循环的上下文压缩

## 不可变边界

压缩不会改写正常模型请求的 `instructions`、工具定义、输出 Schema 或原始任务 Prompt。Skill 正文位于 `instructions`，同样不压缩。固定内容单独超过预算时明确失败，不删除安全约束。摘要是 assistant 历史材料，不提升为 system/developer 指令。

## 范围与策略

### 完整上下文交接修正

摘要请求使用当前上下文的只读副本：原始系统指令（含 Skill）、原始任务与运行上下文、工具和输出格式定义、已有摘要、全部较早历史以及保留的最近回合。上述内容放在参考资料中，摘要专用指令明确其不是本次摘要请求需要执行的操作；末尾追加交接请求，禁用工具并去掉原任务的输出 Schema。运行身份由程序单独提供，原始任务定义目标和边界，摘要只整理执行事实，不根据工具操作猜测或重新定义任务。

优先一次发送完整快照；只有完整摘要请求自身装不下窗口时，才分片累计整理历史，每片都携带完整原始任务、系统边界和程序记录的运行身份。最近回合也是参考材料的一部分，分片不会丢掉它们。固定参考资料本身装不下时明确失败，不截断原始任务或删除权限限制。不可解读的加密推理不作为明文摘要素材。

摘要必须区分已完成检查与需要重查的条件、文件修改、提交/推送、失败操作、待办、下一步和补读引用。交接前缀明确是同一次运行的继续，原始目标不变，不能无理由重做已完成检查或重复提交、推送。替换范围仍只有旧摘要和较早历史；原始系统指令、任务、工具定义、输出格式及保留回合不变，专用压缩指令与草稿不写入正常历史。程序提供的身份与目标依据可减少漂移，但不宣称能完全验证自然语言摘要的语义忠实性。

参考 Codex 的摘要式压缩，使用现有模型客户端生成可跨 Provider 传递的文本摘要，不调用私有压缩协议、不增加 Agent 工具。摘要请求使用独立指令且没有工具；函数调用、空摘要或未完整结束的摘要仍拒绝。摘要超过软目标不构成失败，最终以完整请求预算及是否缩小历史为验收依据。原始执行日志保持不变。

按完整已完成回合维护历史，每组包含模型输出及全部工具结果；未完成的工具调用不参与压缩。旧回合生成任务交接摘要，近期回合尽量保留。窗口较小时可将更多已完成回合并入摘要，不能拆散调用与结果。只有摘要生成成功、尺寸合规且上下文实际变小后才原子替换活跃历史；失败/取消时原历史不变。

摘要包括进展、决策、已执行操作、文件与提交 SHA、测试结论、待办及关键引用，也必须保留尚需补读的工具结果文件路径。超长源材料分片增量归纳，每次归纳携带上一步摘要，调用次数有上限。普通工具结果完整送模；大结果保存为本轮可补读的完整脱敏文件，不再使用不可补读的首尾截断，详见 [工具结果设计](design-tool-result-files.md)。

## 预算

`runtime.context_compaction` 默认启用。窗口优先采用显式 Provider/模型覆盖，其次读取 Codex 当前模型缓存的 `context_window`，否则使用 131072 的默认预算配合保守字节估算；未知模型的实际窗口不作保证，管理员可配置小窗口覆盖。该默认值同时验证能容纳项目已有的长任务 Prompt。默认预留 4096 输出 token，自动触发点为完整窗口的 95%（`trigger_ratio: 0.95`），而不是扣除输出预留后的 95%；若输出预留使安全输入预算更低，则提前在安全输入上限触发。压缩目标仍为输入预算的 50%，尽量保留最近 2 个完整回合。现有显式配置的比例继续生效，但统一按完整窗口计算。

采用 UTF-8 序列化字节数加结构余量进行保守文本估算，不将字符数或本轮累计账单 token 冒充精确上下文用量；日志明确标识为估算。`summary_target_bytes` 默认 2048，只是摘要软目标；旧键 `max_summary_tokens` 仍作为输入别名兼容，序列化使用新键。软目标不会成为窗口配置的硬约束，运行时根据剩余空间调整提示。工具正文阈值 `tool_output_inline_bytes` 默认为 65536 字节，超出时提供完整文件引用；旧 `tool_output_tokens` 忽略，不再限制为 4096 字节。单次压缩最多 16 次模型请求。没有新增 tokenizer 下载依赖。

## 摘要软目标与有界收短修复

只要固定内容、摘要、近期完整回合及输出预留构成的请求处于预算内，并且上下文比原来小，便接受摘要；不因超过 2048 字节或目标压缩比例而拒绝。原请求仍安全但主动摘要未带来缩小时继续保留原历史。

如果完整候选请求仍超限，或者强制恢复时未缩小，则使用更小软目标重新归纳最后一份完整摘要输入。`max_summary_rewrites` 默认 2，收短调用同样计入 `max_compaction_requests` 总上限。超大中间摘要无法装入下一次分片请求时，也重新归纳生成它的输入，不把超限草稿直接发给模型，不裁掉草稿尾部、源材料或系统指令。已有摘要作为源材料参与分片，支持切换到更小模型窗口。

所有草稿及分片进度仅在本次压缩内暂存，最终验收通过才更新活跃上下文；失败、取消和上游回退不提交半成品，不重跑已经执行的工具。空摘要、完整请求超限、未缩小以及请求次数耗尽使用不同错误码，并记录摘要字节数、软目标、输入预算、前后估算量和收短次数。生成过程不新增可执行工具。

每次切换 Provider/模型后重新计算预算。明确 `context_length_exceeded` 时允许本轮候选一次缩小目标上下文并压缩后重试当前请求；压缩本身遇到超限则明确失败，不原样无限重试。不可恢复的上下文错误标记为不可自动重跑整个 Agent。额度/临时上游错误沿用已确认的运行内额度跳过与请求级回退规则。主动压缩未缩小历史、而原请求仍在预算内时，保留原历史继续；真实超限后的强制恢复不适用此例外。

文本摘要有损，系统不保证每个历史细节都能保留。完整脱敏工具结果与摘要日志用于追溯；后续任务需补足证据时应定向读取，不重做已完成的提交、推送等副作用。

## 可观测性与验证

记录压缩开始、完成、失败以及工具结果文件保存，包含模型、请求轮次、预算来源、前后估算量、保留回合、摘要及用量，不含凭据或加密推理内容。新文件事件明确标识不是摘要压缩；旧截断事件仅保留历史显示兼容。摘要输出不混入正常 Agent 最终结果；费用计入运行用量。

回归必须验证系统指令/Skill/原始任务不变、工具完整配对与不重放、跨模型压缩、超大输出与分片、超软目标但有效摘要被接受、完整请求超限时有界收短、空/未完成/工具型摘要拒绝、失败原子性、取消及不触发整轮重跑。

参考：Codex `compact.rs` 与压缩 Prompt（源码提交 `d77ebc72237a639b6d877f2edc3b20b54631f25e`）；[OpenAI Compaction](https://developers.openai.com/api/docs/guides/compaction) 明确指出压缩请求本身也必须能装入模型窗口。本实现使用文本摘要，不混用原生加密 compaction 输出。
