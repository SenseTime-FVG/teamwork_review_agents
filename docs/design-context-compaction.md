# 托管模型循环的上下文压缩

## 原对话副本与交接请求

当前策略见 [原对话副本压缩设计](design-context-fork-compaction.md)。摘要从当前完整活跃对话深拷贝出独立副本，在末尾追加交接请求；不再把对话转为 JSON 资料，不再按字符分片。副本继承原系统指令、任务、已有摘要、近期消息、工具调用与结果结构及当前模型参数。工具定义保留，但强制禁止工具调用；仅解除原任务的输出 Schema。正常请求的 Schema 不受影响。

提示词采用四类交接信息：进展和决策、背景和约束、未完成事项及下一步、关键数据和证据引用。补充禁止工具、准确记录当前工作、跟随最新用户要求，不针对特定 Agent，不强制九个栏目或逐条抄录所有用户消息。提示词来自通用交接思路，不调用私有原生压缩协议，不增加 Agent 工具。

## 不可变边界

原始系统指令、权限约束、Skill 正文、工具定义、输出 Schema 和原始任务 Prompt 均不被摘要替换。成功后只替换旧摘要与较早完整回合，近期调用及结果尽量成组保留。交接请求及失败草稿不进入原对话；空摘要、未完成响应、工具调用、失败或取消均不提交半成品，也不重放工具。

“完整上下文”指当前活跃历史，包括之前压缩形成的摘要；不承诺每次重读全部原始日志。不透明推理项保持当前协议原本可发送的结构，不转为明文摘要素材。文本摘要有损，保留结构不能保证每个事实都正确；关键证据不足时仍应定向回读。

## 预算与有界收短

上下文窗口由 Provider、全局模型、Agent 及各回退项分层解析，系统默认 272000，见 [窗口配置设计](design-context-window-configuration.md)。配置值不代表上游模型实际容量。

默认自动阈值为完整窗口的 90%（`trigger_ratio: 0.90`）；已有显式比例（包括 0.95）继续生效，不改写部署配置。默认预留 4096 输出 token，并为副本末尾的交接及收短提示保留额外空间，取更低的安全触发点。预算仍采用 UTF-8 序列化字节数加结构余量的保守估算，不是精确 tokenizer 或累计账单 token。

目标仍为安全输入预算的 50%，尽量保留最近 2 个完整回合。`summary_target_bytes` 默认 2048，只是提示与保留回合规划的软目标，不是摘要失败上限；旧 `max_summary_tokens` 继续兼容。超过软目标但整体请求能容纳且确实变小时照常接受。

收短最多额外 2 次（`max_summary_rewrites`），并计入 `max_compaction_requests`（默认 16）。每次都从同一原对话重新 fork，仅调整最后交接请求，不追加超限草稿、不裁掉源消息。安全的原请求若没有压缩收益则继续保留，强制超限恢复必须确实缩小。

完整 fork 加交接请求无法装入当前窗口时报告 `context_summary_request_too_large`，保留原历史，不退回分片或截断。切换较小模型时同样检查；窗口配置不匹配、固定内容过大等确定性错误不触发整轮 Agent 重跑。摘要请求遇到额度或临时 Provider 故障仍沿用原有请求级回退；已执行工具不重放。

## 工具结果与运行记录

普通工具结果仍完整脱敏返回。大结果超过正文阈值（默认 65536 字节），或当前完整历史加本轮结构、交接预留后装不下时，使用现有可补读结果文件，不丢弃原内容、不新增读取工具，详见 [工具结果设计](design-tool-result-files.md)。`enabled: false` 只关闭摘要，不关闭文件与资源保护机制。

记录压缩开始、成功、失败、收短、用量和窗口来源，标识 `summary_context_mode=fork`，展示实际阈值、请求大小及提示预留量。记录中不包含密钥或加密推理，摘要不混入最终 Agent 答复。原始执行日志不改写，整个副本摘要使用独立模型请求而不是新 Agent 或 Git 分支。

## 验证范围

覆盖完整消息前缀及工具配对、原系统和参数继承、副本嵌套对象隔离、多次通用任务交接、各协议禁用工具、90% 默认与显式 95%、安全上限、完整副本超限、有界收短、取消、失败原子性、Provider 回退、不重放工具和完整工具结果补读。测试验证程序边界，不将模拟模型输出当作真实摘要语义保证。

参考：[Codex 文本交接提示词](https://github.com/openai/codex/blob/e269f2164cbb9f499e4f22301c393500e2a831f3/codex-rs/prompts/templates/compact/prompt.md)；本地 open-claude-code 的副本交接策略。本项目使用可跨 Provider 的文本摘要，不混用原生压缩状态。
