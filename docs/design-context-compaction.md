# 托管模型循环的上下文压缩

## 不可变边界

压缩不会改写正常模型请求的 `instructions`、工具定义、输出 Schema 或原始任务 Prompt。Skill 正文位于 `instructions`，同样不压缩。固定内容单独超过预算时明确失败，不删除安全约束。摘要是 assistant 历史材料，不提升为 system/developer 指令。

## 范围与策略

第一版参考 Codex 的摘要式压缩，使用现有模型客户端生成可跨 Provider 传递的文本摘要，不调用私有压缩协议、不增加 Agent 工具。摘要请求使用独立指令且没有工具；返回函数调用、空摘要或超长摘要均视为失败。原始执行日志保持不变。

按完整已完成回合维护历史，每组包含模型输出及全部工具结果；未完成的工具调用不参与压缩。旧回合生成任务交接摘要，近期回合尽量保留。窗口较小时可将更多已完成回合并入摘要，不能拆散调用与结果。只有摘要生成成功、尺寸合规且上下文实际变小后才原子替换活跃历史；失败/取消时原历史不变。

摘要包括进展、决策、已执行操作、文件与提交 SHA、测试结论、待办及关键引用。超长源材料分片增量归纳，每次归纳携带上一步摘要，调用次数有上限。超大工具结果只在送模副本中保留首尾和截短标记；原始结果仍在日志中。

## 预算

`runtime.context_compaction` 默认启用。窗口优先采用显式 Provider/模型覆盖，其次读取 Codex 当前模型缓存的 `context_window`，否则使用 131072 的默认预算配合保守字节估算；未知模型的实际窗口不作保证，管理员可配置小窗口覆盖。该默认值同时验证能容纳项目已有的长任务 Prompt。默认预留 4096 输出 token，达到输入预算的 80% 时压缩，目标为 50%，尽量保留最近 2 个完整回合。

采用 UTF-8 序列化字节数加结构余量进行保守文本估算，不将字符数或本轮累计账单 token 冒充精确上下文用量；日志明确标识为估算。默认摘要预算 2048、单个工具结果送模预算 4096，单次压缩最多 16 次模型请求。没有新增 tokenizer 下载依赖。

每次切换 Provider/模型后重新计算预算。明确 `context_length_exceeded` 时允许本轮候选一次缩小目标上下文并压缩后重试当前请求；压缩本身遇到超限则明确失败，不原样无限重试。不可恢复的上下文错误标记为不可自动重跑整个 Agent。额度/临时上游错误沿用已确认的运行内额度跳过与请求级回退规则。主动压缩未缩小历史、而原请求仍在预算内时，保留原历史继续；真实超限后的强制恢复不适用此例外。

文本摘要有损，系统不保证每个历史细节都能保留。完整脱敏工具结果与摘要日志用于追溯；后续任务需补足证据时应定向读取，不重做已完成的提交、推送等副作用。

## 可观测性与验证

记录压缩开始、完成、失败及工具输出截短，包含模型、请求轮次、预算来源、前后估算量、保留回合、摘要及用量，不含凭据或加密推理内容。摘要输出不混入正常 Agent 最终结果；费用计入运行用量。

回归必须验证系统指令/Skill/原始任务不变、工具完整配对与不重放、跨模型压缩、超大输出与分片、空/超长/工具型摘要拒绝、失败原子性、取消、超限重试有界及不触发整轮重跑。

参考：Codex `compact.rs` 与压缩 Prompt（源码提交 `d77ebc72237a639b6d877f2edc3b20b54631f25e`）；[OpenAI Compaction](https://developers.openai.com/api/docs/guides/compaction) 明确指出压缩请求本身也必须能装入模型窗口。本实现使用文本摘要，不混用原生加密 compaction 输出。
