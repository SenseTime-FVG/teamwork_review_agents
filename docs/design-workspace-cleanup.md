# 运行工作区定时清理设计

## 范围与默认行为

只清理 `data/worktrees/<仓库标识>/<run_id>` 下已确认归属且过期的运行工作区，不清理下载缓存、安装快照、数据库或基础仓库。默认开启，每天服务主机本地时间 06:00 检查，保留期为 7 天。

计划支持固定间隔（小时、天）、每小时指定分钟、每天指定时分、每周指定星期和时分。使用主机本地日历处理定点时间，不使用浏览器时区或写死时区。启动只恢复未来计划；停机错过的周期不补跑，重启不会立即删除。间隔计划的未来触发点持久化，避免重启不断延后。

## 安全边界

- 有效外部保留标记、受管目录层级和数据库运行路径必须相互吻合；符号链接、目录联接、路径越界和缺失归属证据均拒绝清理。
- 保留期以运行结束和保留标记时间的较晚者起算，采用当前已保存的保留天数；缩短保留期会影响已有工作区。
- 清理和运行共享工作区使用租约，父子运行按根任务重入；取得清理锁后再次检查活动运行及共享路径。活动根任务、排队、准备或运行中的任务均受保护。
- 独立 clone 的删除校验不要求没有 alternates；只删除其自身目录，不修改或遍历借用的基础对象库。linked worktree 只有确认基础仓库归属后才通过 Git 删除，否则保留并说明原因。
- 仓库停用或移除不影响已确认受管 clone 的回收。未知目录一律跳过，不凭名称推断归属。
- 清理独立串行执行，逐目录在线程中处理并让出事件循环；迁移期间不得运行。服务退出等待当前删除收尾，不中断文件系统操作。

## 可观察性与界面

配置历史上方显示独立“工作区清理”卡片。配置沿用页面草稿、保存和取消行为，原保留期输入移到此处。显示后台格式化的最近和下次执行时间、清理数量、释放字节及展开详情，不显示时区。失败和跳过不静默吞掉，并更新对应运行记录与清理日志。

## 验证

仅使用临时目录测试删除。覆盖计划计算、重启不补跑、配置热加载、本地时间和夏令时、安全路径、并发租约、活动父子任务、旧 clone、停用或移除仓库及删除失败。现有真实数据不用于删除测试，也不重启部署服务。
