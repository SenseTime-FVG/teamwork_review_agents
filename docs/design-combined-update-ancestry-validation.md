# 组合更新入口祖先校验修正

## 问题

PR #108 的入口运行将 `git merge-base --is-ancestor` 的两个参数倒置，把“当前目标分支不是旧合并提交的祖先”误判为“合并提交已不在目标分支历史中”。现场正向检查返回 0，反向检查返回 1，属于正常的目标分支推进。

原入口只有自然语言约束，没有固定命令；现场还将所有非零退出码都归为关系不成立，可能混淆对象缺失等 Git 执行异常。

## 方案

- 将平台已核验的完整合并前、合并后 SHA 分别绑定为 `MERGE_BEFORE_SHA`、`MERGE_AFTER_SHA`。
- fetch 成功后固定远程目标分支完整 SHA 为 `TARGET_HEAD_AT_START`，校验通过后才可用于后续流程，不能重新赋值掩盖漂移。
- 固定两项正向检查：合并前到合并后、合并后到启动目标 HEAD；禁止用反向检查代替。
- 分别捕获命令退出码和 stderr：0 通过，1 关系不成立，其他值为无法验证。历史不完整时不能断言历史改写。
- 最终报告保留每项检查证据，未执行项不得推断通过。

## 边界

不改变组合分支基点、子 Agent 协议、目标分支漂移门禁、写权限或清理规则。不改变平台 `completed` 与模型业务结论的映射，不修改历史记录，不重跑真实任务。

这是 Prompt 约束修正，不是新增宿主侧强制 Git 门禁；回归测试验证模板与 Git 语义，不能保证模型绝不会偏离指令。
