# 子 Agent 等待、超时与取消设计

## 问题与边界

内嵌模型模式中，父 Agent 等待 `invoke_agent` 时没有自身输出，旧看门狗会在 300 秒后误判无进展。取消沿协程传播到子 Agent 后又被转换成“管理员取消”，父循环还可能吞掉中断继续执行。

本次只修复内嵌运行调度，不改变 Prompt、模型接口、默认时限、重试配置或完整 Codex CLI 内部的等待策略。不向父模型同步子任务日志、消息或心跳，不查询数据库日志来伪造进展。

## 运行规则

- 每个运行有独立的控制状态，通过异步上下文隔离并保留父控制状态引用。
- 等待子任务期间只暂停父运行的无进展判断；总时限与人工取消、服务停止仍然有效。子任务继续使用自己的无进展与总时限判断。
- 子任务退出等待（成功、失败、中断）时重新开始父运行的无进展计时。嵌套调用逐层使用同样规则。
- 排队和准备阶段仍受现有阶段限制与父运行总时限约束，不无限等待。
- 自动超时、管理员取消、服务停止、父任务中断、未知上层中断必须区分。没有明确管理员来源时不能声称“由管理员取消”。
- 中断是单向终态：已触发的父任务停止原因不能因子任务返回或异常被捕获而清除；后续模型、工具不得继续执行，也不能以 completed 结束。
- 执行器在清理并确认取消来源后统一持久化一次取消终态日志；子任务自身超时返回包含错误码的失败结果，不冒充父任务被人工取消。

## 验证

使用模拟模型与临时测试数据库，覆盖活跃子任务超过父 idle、子任务自身 idle、等待后的父 idle 重置、父总时限、人工取消、服务停止、嵌套等待、排队中断、吞取消的工具以及取消日志去重。不启动真实 Agent，不改历史运行或实际配置。
