# 依赖缓存闲置清理设计

## 目标与边界

依赖下载缓存与工作区依赖快照位于 `data/preflight-cache/<仓库身份>`，原有工作区保留期不覆盖这里。本次复用现有定时清理计划，增加独立的 `runtime.dependency_cache_retention_days`，默认闲置 7 天。只删除受管缓存，不删除数据库、日志、凭据和基础仓库，不添加硬容量淘汰，也不重启后台或重放任务。

## 使用与并发保护

- Agent 完整运行、自动及手动 Preflight、工作区预热在首次创建缓存前取得共享文件锁，直至缓存使用结束；多个任务仍可并行共享缓存。
- 清理器只尝试非阻塞独占锁，忙碌时跳过。锁文件放在缓存外的专用目录，不随缓存删除，进程退出后由系统释放，不依赖心跳到期推断仍在使用的目录已空闲。
- 在使用开始和结束时原子更新受管元数据的最近使用时间，长任务按完成使用时间起算；扫描与展示不刷新有效使用时间。
- 版本、缓存名称和时间字段须严格校验。首次发现无元数据的旧缓存，仅登记并给予完整保留期；损坏、链接、联接及不符合受管命名的目录保留并说明原因。
- 额外检查活动 Agent / Preflight 的仓库或缓存引用，兼容尚未取得文件锁的旧运行；无法识别活动任务归属时保守跳过。

## 清理过程与展示

工作区兜底清理完成后检查缓存，保留期未到、被使用、配置变化或仓库迁移时跳过。删除前持锁重新检查时间、配置、活动任务和目录身份，不跟随符号链接。当前配置已不再引用的受管旧缓存同样适用闲置保留期。

沿用工作区历史统计字段，新增独立的依赖缓存统计和有界详情，避免旧界面将缓存数量误解为工作区数量。现有配置历史上方的清理卡片展示两类数量、回收空间及跳过/失败原因，缓存保留期参与编辑草稿、保存和缩短期限提示。

## 本次存量清理

已按现有 7 天保留规则删除 8 个过期工作区，并在确认无活动任务、当前配置不再引用后删除两个旧缓存目录。`data` 实占由 14,400,888 KiB 降到 7,840,060 KiB，约回收 6.3 GiB。保留未到期目录、归属不明的旧目录及完整运行历史；已删除的依赖缓存可重新下载，过期工作区内未保存的临时内容不承诺恢复。
