# 跨平台 CI 稳定性修复设计

## 背景

PR 同一提交在 Windows 的 `push` 与 `pull_request` 检查中均在测试收集阶段失败，原因是工作流仍引用已经改名的测试节点。Ubuntu 的 `pull_request` 检查则在多实例停止测试中取得 `-15` 退出码，而相同提交的 Ubuntu `push` 检查通过。

## 问题分析

Windows 工作流只运行一组与平台相关的定向测试。Provider Token 环境隔离测试改名后，工作流中的 pytest 节点 ID 没有同步更新，导致 pytest 找不到测试并直接退出。

POSIX 平台停止托管进程时会发送 `SIGTERM`。被停止进程既可能完成 Uvicorn 的正常收尾并返回 `0`，也可能直接以 `SIGTERM` 对应的 `-15` 退出。两种结果都表示进程已经按预期停止；现有测试只接受 `0`，因此会受调度时序影响。

## 修复方案

- 将 Windows 工作流引用更新为当前存在的 Provider Token 环境隔离测试名称。
- 多实例停止测试显式接受正常退出和 `SIGTERM` 退出，同时继续校验停止操作成功、全部目标 PID 被报告，以及配置下不再存在运行中的托管进程。
- 不修改生产环境的进程停止逻辑，不改变运行时行为。

## 非目标

- 不调整工作流同时监听 `push` 与 `pull_request` 的现有策略。
- 不扩大 Windows 定向测试范围。
- 不改变服务停止信号、超时或强制终止策略。
