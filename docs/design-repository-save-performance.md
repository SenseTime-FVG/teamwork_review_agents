# 仓库保存与状态轮询性能

仓库保存前调用完整状态查询，查询最近 Agent 运行时缺少排序索引。历史运行行内包含大段审计数据，扫描及临时排序会读取大量溢出页；页面每两秒发起新查询，慢请求互相重叠并占用共享线程，保存也被拖入等待。现场最近一条运行查询耗时约 4.87 秒，数据库约 4.1 GiB。

增加按开始时间和运行 ID 排序的覆盖索引，同时优化现有运行列表和仓库最近运行查询。仓库状态只读取运行 ID、状态、开始和结束时间，不读取事件正文或运行审计材料；保留显式仓库字段、关联事件及旧资源键的归属兼容规则。

保存前独立检查进程内手动 Git 操作及数据库中的 preparing 运行，使用活动记录的部分索引，不检查 Git 目录、计算目录大小或读取历史列表。较早的 preparing 运行仍须阻止保存，不能被后来完成的运行掩盖。普通运行中状态保持原有保存规则。

服务端对同配置版本、同仓库的并发状态读取共享进行中的任务，不缓存完成结果。前端状态和预热轮询分别合并进行中的请求，保存时暂停定时刷新；保存成功后异步刷新状态，按钮与成功反馈不等待列表请求。取消一个读请求不能取消其他读取者共用的服务端任务。

配置校验、版本冲突、Secret 脱敏、目录迁移和真实忙碌保护保持现有语义。此改动不执行依赖安装，不更改仓库配置内容或已有运行历史。
