# 自动本地 CI 失败诊断

每个仓库启用本地 CI 后默认开启失败诊断并使用内置 Agent，也可手动关闭或指定其他 Agent。旧配置未声明诊断开关时按开启处理，明确关闭的配置不被覆盖。首次加载配置提供可编辑、可删除的内置 `ci-failure-diagnoser`，模型和 effort 沿用 Agent 配置。通过版本标记只初始化一次，删除后保留仓库引用并跳过诊断，重启不会恢复。

自动 MR/PR CI 的失败、超时和重试耗尽的基础设施异常触发诊断。按 CI run ID 原子去重；复用历史 CI 不重复调用模型。诊断状态、报告、关联 Agent 运行及评论错误独立持久化，CI 原始终态不受影响。取消、服务中断和模型错误均可在详情页查看。

诊断复用 Agent 执行审计、额度、模型回退、轮次及取消控制，通过模型工具提供分页日志检索和固定 SHA 源码读取。诊断不执行仓库准备脚本，避免因相同依赖错误再次阻塞；只读工具没有执行命令、改文件、发布评论和子 Agent 的能力。无法取得对应源码时仍可基于日志报告限制。

报告在 CI 详情中展示并可复制 Markdown；启用现有失败评论开关时由服务端补充到当前失败评论。发布前核对最新 CI 与源版本，并共用评论锁，防止旧报告覆盖新结果或在成功后重建失败评论。

取消和已被新提交取代的 CI 不触发诊断。手动默认分支 CI/缓存预热维持现有行为。
