# 沙盒进程标记读取竞态实施方案

1. 给现有进程取消测试增加确定性发布竞态参数，仅对 PID 标记覆盖存在性检查。
2. 在原实现上执行新增参数，记录预期失败，确认不是仅靠重复执行捕获随机竞态。
3. 将模拟冲突改为真实读取成功后注入，保持非目标文件读取及真实异常的语义。
4. 执行全部参数与重复竞态验证，运行沙盒和进程管理相关测试以及完整测试套件。
5. 执行编译与差异检查，仅提交本任务的测试和文档，然后推送当前分支。
6. 检查推送触发的 GitHub Actions；区分本地验证与实际平台检查结果。

## 验证结果

- 旧读取逻辑下，新增发布竞态场景以 `assert 0 == 2` 确定性失败。

- 两种读冲突场景分别重复执行十次，共二十次全部通过。
- 沙盒环境与进程管理相关测试：`77 passed, 6 skipped`。
- 仅包含基线提交 `44795b7` 和本次测试修改的临时副本完整测试：
  `1431 passed, 38 skipped, 2 warnings`，耗时约 124 秒；没有混入其他未提交改动。
- 本地解释器为 Python 3.14；完整源码与测试编译检查通过，差异空白检查通过。
- 远程工作流使用 Python 3.12，实际三平台结果以 PR #32 的 GitHub Actions 为准，
  本地通过不替代原生 Windows 等平台验收。
