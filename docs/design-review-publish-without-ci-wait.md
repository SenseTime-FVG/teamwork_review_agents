# 仅审核模式不等待远端 CI

## 行为

仅审核模式完成完整代码、设计、历史契约和一致性审核后，直接发布最终代码审核结论。发布前仍刷新源与目标 SHA、平台状态及当前源提交的 CI 状态；CI 仍在运行时如实记录，不调用 `wait_for_ci`，不通过命令或循环等待 CI。

CI 运行中引起的平台暂不可合并或检查中，不作为终止完整代码审核或延迟最终评论的理由。明确的冲突、草稿、必要审批和讨论等其他门禁保持原规则；当前源提交的远端 CI 明确失败仍沿用既有终止规则。源或目标 SHA 变化仍结束且不发布过期结论。

评论区分代码审核结论与 CI、合并门禁状态。完整审核可以在 CI 运行中发布“代码审核通过；CI 仍在运行；未执行合并”，不能因此声称 CI 或所有合并门禁通过，也不能仅因 CI 未结束将完整审核降为部分。

自动合并模式仍等待 CI 并满足现有平台门禁后处理合并。通用 CI 等待工具继续可用，共享运行时说明改为仅在任务需要等待时适用，不覆盖角色 Prompt 的不等待要求。

## CI 等待工具可见性

使用 `REVIEW_AUTO_MERGE` 模板变量的审核 Prompt，按本次已解析且实际暴露给 Prompt 的值确定工具可见性；只有显式 `true` 才保留 `wait_for_ci`。默认或仅审核模式不提供该工具。不使用此变量的普通开发、依赖更新等 Agent 保留原有工具，不依赖 Agent 名称、评论槽位或全局同名变量猜测任务类型。

模板变量通过 Jinja 语法树识别，兼容旧变量语法；普通文字和注释中的同名词不触发过滤。判定结果固定在服务签发的运行上下文中，内嵌模型工具列表、CLI 启用列表、直接 MCP 和沙盒代理目录使用同一值。子 Agent 按自己的 Prompt 和配置独立判定，旧调用上下文默认保留原有工具。

未提供的等待工具被旧模型消息误调用时，在调用入口返回不可用，不创建 CI 等待记录或平台查询。本次不增加审核完成度校验、自动续审或新的 UI 配置项。

## 范围

审核规则仍由 Prompt 控制；工具可见性按上述运行上下文分发。保持通用执行结果和评论接口，不新增完成度校验、输出协议或状态约束，不修改用户仓库配置、历史评论，不重放审核。
