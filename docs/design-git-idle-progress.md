# Git 无进展超时与实时进度

## 行为

基础仓库初始化及其他托管 Git 命令改为无有效进展超时，不再限制命令总耗时。沿用 `runtime.repository_initialization_timeout_seconds`（首次克隆，默认 1800 秒）和 `runtime.git_timeout_seconds`（其他命令，默认 600 秒），兼容已有配置键。锁等待超时和模型执行超时保持独立。

有效进展只来自 Git 标准进度中的阶段、对象/文件数量、接收字节数推进或阶段完成。相同进度重复输出、速度变化、任意文本、心跳、轮询和进程存活不延长超时。没有可量化进度的命令从启动开始计算无进展时间。所有阶段均没有总时长硬上限；取消仍终止整个进程树。

## 采集与安全

clone、fetch、checkout 强制输出进度，Git 子进程使用 C 语言环境。独立读取线程持续消费 stdout/stderr，兼容 Windows 管道，不依赖 `communicate` 超时异常携带中间输出。stderr 使用有界缓冲和有界逐行解析，支持回车刷新、拆包和 UTF-8；stdout 保留原返回值供 Git 查询使用。

仅白名单解析标准阶段并输出固定阶段名、数字、字节数和速度。原始输出不进入进度事件、SQLite 或管理 API。失败摘要先脱敏再限长。每秒最多推送一次最新状态，心跳不改最近有效进展时间。使用单调时钟计算超时，墙上时钟仅用于显示。

## 界面

Git 详情显示阶段进度条（不是整个仓库的总体百分比）、对象/文件数、接收大小、传输速度、总耗时、无进展时长及最近有效进展时间。没有已知百分比时显示等待 Git 报告进度，不伪造百分比。无有效进展超过一分钟时提示可能停滞，但只有达到配置阈值才失败。旧记录缺少新增字段时仍可展示，并标明旧的总超时语义。

运行中的旧服务任务不能热切换进程执行逻辑；部署新版本并重启后的新 Git 命令才使用新行为。不得为了更新代码擅自中断现有任务。
