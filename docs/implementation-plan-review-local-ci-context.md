# 审核本地 CI 门禁上下文实施方案

1. 增加结构化本地门禁摘要，区分已通过与已跳过，不传入原始 CI 日志。
2. 在编排器启动事件 Agent 时生成摘要，成功结果严格关联当前仓库、编号及源 SHA；跳过路径说明真实原因。
3. 执行器把摘要写入运行 Prompt，并通过可信调用上下文保留到子 Agent；不复用 CI 失败诊断的授权字段。
4. 修改通用审核 Prompt：移除本地 Preflight 的重复判断，保留远端 CI 和平台门禁；补充验证与正式门禁分开报告。
5. 同步使用文档与现行设计说明，覆盖失败仍不启动、成功及复用、各类跳过、平台差异、委托继承、源版本关联和模板渲染回归。
6. 运行相关测试、完整后端测试、编译和差异检查，仅提交本次变更并自动推送；保留无关文件，不修改本机运行配置或历史记录。

- 在普通临时目录导出当前 HEAD，并仅覆盖本次修改，隔离工作区中尚未完成的其他 CI 附件改动；没有创建分支或 Git worktree。
- 完整后端测试：`python -m pytest`，1729 项通过、38 项按平台条件跳过；两条已有依赖弃用警告不影响结果。
- 已覆盖本地失败阻断、成功及复用摘要、三类跳过、源版本错配拒绝、根任务与子任务传递、两种委托边界和旧调用兼容，远端 CI 与审批门禁回归通过。
- Python 编译检查和 `git diff --check` 通过。
