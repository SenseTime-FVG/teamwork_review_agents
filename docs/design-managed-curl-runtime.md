# Windows curl 自动准备设计

## 默认体验

Windows 服务启动时异步检查已有兼容 curl，缺少时准备项目专用固定版本。管理 UI 和扫描循环不等待下载；首次事件分发与定时任务仅等待这次有界准备结束，失败后仍按原有可恢复语义继续。下载不是 Agent 工具，不在每个运行里下载。非 Windows、关闭托管沙盒、关闭自动准备及显式配置 curl 路径时，不自动下载。

## 分发与安全

固定 curl 官方 Windows `8.22.0_1` 的 x64 / ARM64 ZIP URL 和 SHA-256，禁止 latest 漂移和任意 URL。官方构建静态链接 LibreSSL，包含 CA 文件；用户不需要单独安装 OpenSSL。服务仅下载公共安装包，不携带业务 Token，保持 TLS 验证与服务代理；下载超时、体积、展开大小、文件数量均有上限。拒绝重定向到不受控下载源、ZIP 路径穿越、链接和 Windows 特殊路径。

缓存位于数据库目录旁的 `runtimes/curl`，不放进 Agent 可写工作区或临时 HOME。跨进程发布锁防止重复下载；校验后在独立临时目录展开并原子发布，取消时清理本次临时文件。损坏缓存隔离保存，禁止无条件删除未知目录。版本缓存与官方 ZIP 一起保留，后续通过固定归档校验值验证运行文件，不能仅凭自行生成的 ready 标记信任可执行文件。

离线部署将同名官方 ZIP 放到状态页面显示的 `downloads` 路径，使用相同校验与发布逻辑。安装后及复用已有程序前，使用实际 Windows 外层沙盒直接执行无凭据、禁网的 curl 版本探针，不经服务 Python 启动桥。程序无法执行时记录权限/启动/后端原因，不把网络、CA、域名策略问题当成缺少程序而重装。实际 HTTPS 仍由每个 Agent 在自己的网络边界内检查。

## 生命周期与界面

后台管理器提供已就绪、准备中、不可用、已禁用、不适用状态，以及来源、路径、错误码和离线包路径。GET 只查询，不触发安装；受现有管理员鉴权保护的 POST 允许重试。并发重试合并为同一准备任务。关闭服务取消网络/探测进程并等待清理，不遗留后台下载。

全局配置页直接显示状态与重新准备入口；手动 curl 路径收进高级配置。运行时间线中的可恢复 curl/HTTP 能力问题使用告警样式，不冒充 Git 致命失败。配置变化重新进行一次准备；不会根据模型输出触发安装或放宽权限。

面板操作按钮复用 `button secondary` 完整样式类，准备中沿用禁用样式并声明忙碌状态。离线包链接的正常、已访问和悬停颜色，以及面板内键盘焦点均适配暗色背景；样式仅限定本面板，不改变告警内容或沙盒权限逻辑。
