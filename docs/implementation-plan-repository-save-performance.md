# 仓库保存性能实施计划

1. 增加运行摘要排序覆盖索引及 preparing 部分索引，提供轻量最近运行和准备状态查询，兼容旧记录的仓库归属。
2. 仓库状态使用轻量摘要；并发读取共享进行中的任务，完成后移除，不形成过期状态缓存。
3. 保存、删除仓库前仅查询必要的活动状态，保留手动 Git 与 Agent 工作区准备保护。
4. 前端轮询增加请求合并，保存期间暂停定时刷新，成功反馈不等待列表刷新。
5. 验证旧记录归属、排序同时间边界、大字段读取成本、早期活动任务、并发与取消、保存隔离及前端重试；运行全量后端测试和前端测试、构建。
6. 提交并推送，空闲时重启后台，在现有数据库验证索引迁移、接口耗时和健康状态。

## 验证结果

- 后端全量 1951 项通过、10 项跳过；前端 130 项通过，TypeScript 与 Vite 构建通过。
- 现有数据库补齐两个索引耗时约 4.63 秒。既有最近运行查询由约 4.87 秒降到 5～11 毫秒，轻量摘要约 1～4 毫秒，准备状态检查约 1～3 毫秒。
- 索引生效后只读接口实测：仓库状态约 217 毫秒、最近运行列表约 25 毫秒；验证没有改写仓库配置或运行历史。
