# 工作区准备输出分块测试修复设计

## 根因

提交 `333f789` 的 macOS push 检查在工作区准备测试失败，同一提交的 PR 检查通过。
失败时准备命令、缓存目录和准备文件已验证成功，只有日志事件列表的精确比较失败。

子进程输出按 `StreamReader.read()` 返回的数据块产生实时事件；`prepared\n` 可以一次
读取，也可以拆为多次。测试错误地假定命令输出只产生一条事件，因此受平台和调度影响。

## 方案

- 保留真实准备命令、工作目录、缓存路径及第二次运行恢复快照的验证。
- 对非输出的生命周期事件继续严格校验顺序和次数。
- 校验输出事件流类型、所属阶段及拼接后的完整正文，同时核对最终执行结果中的正文。
- 增加正常读取、最多八字节及逐字节读取三个场景，强制分块场景必须实际产生多块输出。
- 仅在测试进程内限制读取块大小，不修改生产日志或运行时行为。

## 验证

新增八字节场景在原断言下必须复现多一条输出事件的失败；修复后运行三个场景、
重复强制分块测试、相关准备和 Preflight 测试、完整套件及编译检查，并核对远程 CI。
