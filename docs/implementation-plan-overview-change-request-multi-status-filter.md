# 已扫描 MR / PR 多状态筛选实施方案

## 前端

1. 为概览筛选状态增加具体状态数组。
2. 新增紧凑型多选下拉组件，沿用现有下拉框的定位、键盘导航和视觉样式。
3. 仅在“已扫描 MR / PR”列表启用多选状态控件。
4. 查询构造器为每个选中状态追加一个 `status` 参数。
5. 筛选条件变化时回到第一页，并保持空结果提示准确。

## 后端

1. `/api/change-requests` 接收零个、一个或多个 `status` 参数。
2. 快照列表和计数方法兼容字符串与状态序列。
3. 多状态查询生成参数化 `IN` 条件，避免字符串拼接状态值。

## 测试与验证

1. 状态存储测试覆盖单状态与多状态联合查询。
2. Web API 测试覆盖重复 `status` 参数、分页总数和非法状态校验。
3. 执行 Python 定向测试与前端生产构建。
