# 概览与运行记录多状态筛选实施方案

## 前端

1. 复用现有紧凑型多选下拉组件，统一三处状态筛选的交互和视觉样式。
2. 在“最近变化事件”启用概览多状态数组，查询构造器为每个选中状态追加一个 `status` 参数。
3. 为“运行与日志”的筛选状态增加状态组数组，并为每个选中值追加一个 `status_group` 参数。
4. 前端合并 Agent 与 Preflight / CI 记录时，使用多状态组 OR 语义进行一致的兜底过滤。
5. 概览筛选条件变化时回到第一页，并保持空结果提示准确。

## 后端

1. `/api/events` 接收零个、一个或多个 `status` 参数。
2. 事件列表和计数方法兼容单个状态与状态序列，并生成参数化 `IN` 条件。
3. `/api/runs` 和 `/api/preflight-runs` 接收零个、一个或多个 `status_group` 参数。
4. 将多个语义状态组分别展开、去重为 Agent 与 Preflight / CI 的实际状态集合，再复用已有集合查询能力。
5. 保留精确单状态 `status` 参数，并继续禁止其与 `status_group` 同时使用。

## 测试与验证

1. 状态存储测试覆盖事件单状态与多状态联合查询及计数。
2. Web API 测试覆盖事件重复 `status` 参数、分页总数和非法状态校验。
3. Web API 测试覆盖 Agent 与 Preflight / CI 的重复 `status_group` 参数及精确状态冲突校验。
4. 执行 Python 定向测试与前端生产构建。
