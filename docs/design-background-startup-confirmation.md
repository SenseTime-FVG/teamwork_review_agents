# 后台启动确认设计

## 问题与行为

原生 Windows 的后台启动确认默认等待 30 秒，POSIX（包括 WSL）只等待 5 秒。Python 导入、配置加载、PID 文件写入或健康接口就绪较慢时，`start` 会在服务仍正常启动的过程中终止子进程。

所有平台统一默认等待 30 秒，确认成功立即返回。`start` 和 `restart` 提供 `--startup-timeout SECONDS`，只影响本次新服务的启动确认，不改变停止超时、Git 超时或 Agent 超时。参数必须为有限正数，非法参数在启动或停止任何服务之前被拒绝。

## 健康检查与诊断

健康请求使用独立的无代理 HTTP opener，直接访问配置监听地址对应的本机健康接口，不修改服务、Git 或模型使用的代理环境。仍同时验证 PID 文件、进程身份与健康响应 PID，不能仅凭端口可访问判断成功。

等待结束时报告最后未满足的条件：PID 文件未就绪、PID 文件身份不匹配、进程身份检查未通过、健康连接失败或超时、HTTP/响应格式错误、健康响应 PID 不匹配。保留后台日志路径和末尾日志；子进程提前退出仍立即失败，确认超时继续只收尾本次启动的子进程。

## 验证范围

覆盖延迟超过 5 秒仍成功、默认值及显式覆盖、非法参数在 restart 前被拒绝、代理不影响健康直连、超时原因与 PID 不匹配、失败清理，以及既有真实启动/停止/重启集成测试。
