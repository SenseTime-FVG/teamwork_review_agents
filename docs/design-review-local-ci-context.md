# 审核 Agent 的本地 CI 门禁上下文

## 背景与目标

本地 Preflight 已由编排器在启动要求 CI 的审核 Agent 前执行，但成功结果此前只保存在数据库和事件关联中，没有进入模型输入。模型因此可能把“未收到本地结果”写成 CI 缺失，并把自身受限环境中的额外测试失败混同为正式门禁失败。

本次将本地门禁判断留在后台，审核 Prompt 只负责远端 CI 与代码审核。本地门禁摘要只用于准确说明本轮执行事实，不要求模型查询、补跑或重新判定。

## 上下文与边界

- 为事件触发的 Agent 传入独立的 `local_preflight`，状态为 `passed` 或 `skipped`，包含仓库、变更请求编号、源 SHA 和说明。
- `passed` 必须来自本次编排取得的成功结果，并核对仓库、编号和源 SHA；附带运行 ID 和是否复用，不携带原始日志、命令或凭据。
- 规则不要求 CI、仓库未启用 CI、变更请求已关闭或合并时分别标记跳过原因；未执行不得写成通过。
- 上下文跟随可信调用信息传入子 Agent，两种调用方式均保留；模型提供的委托补充内容不能覆盖该字段。
- 原有失败、超时、异常、取消和被新版本替代的门禁结果继续阻断受约束的 Agent，不改变直接运行规则、CI 幂等和状态回写逻辑。
- 定时、旧调用方或独立使用审核 Prompt 时可能没有该字段。模型只能说明未提供，不推测成功，也不因此增加查询、补跑或阻断要求。

## 审核规则

远端 Pipeline、Checks、Commit Status 仍按当前源 SHA 校验，失败终止、运行中等待及平台实际合并保护保持不变。即使平台将本地 CI 展示为 Commit Status，也不得忽略平台真实失败或绕过保护。

模型自主补跑的测试列为补充验证。缺依赖、收集失败或沙盒权限不足属于环境限制，不改写后台本地门禁，不自动终止完整审核或判定业务缺陷；真实可复现的代码失败仍按证据和阻塞标准处理，不能因后台 CI 成功而忽略。

## 兼容与非目标

字段为可选，不新增数据库表或迁移；执行记录中的完整 Prompt 保留摘要供审计。CI 失败诊断的 `preflight_run_id` 仍是独立的工具授权字段，不能与普通审核的门禁摘要混用。

不修改本机配置、历史评论或历史运行，不重放任务、不重跑 CI、不重启正在工作的后台。
