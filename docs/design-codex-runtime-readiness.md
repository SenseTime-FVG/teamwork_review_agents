# Codex 运行时就绪检查

## 问题与边界

Windows 后台进程继承启动时的 PATH，可能无法解析桌面终端能使用的 Codex。当前检查发生在独立工作区创建之后，失败缓存与通用事件重试进一步造成重复准备。

本次只修复运行时解析、能力检查与确定性失败调度，不修改用户配置、系统 PATH 或沙盒权限。

## 设计

- Codex 专用解析器优先使用显式路径，其次服务 PATH；只有默认 `codex` 名称才允许发现当前服务账户 LOCALAPPDATA 下的桌面安装。显式错误路径不降级。哈希目录按文件修改时间排列，候选须通过版本探测，不把哈希当语义版本。
- 每次运行在工作区创建前检查实际所需能力，将绝对路径绑定在运行上下文；执行器、工具、账户和连接诊断共用解析入口。
- 能力探测只缓存成功结果；缓存键包括实际路径、文件指纹、相关探测环境与配置目录，失败恢复后能重新检查。
- Codex 缺失、固定版本不匹配、确定缺少必需能力使用结构化错误码且不自动重试；超时、启动瞬态异常仍可重试。不得对任意 FileNotFoundError 全局禁用重试。
- Agent 与事件持久化 retryable/error_code；混合事件只重试仍可重试的失败分支，已阻断分支保持原记录。手动触发使用新事件，可在修正配置后重新检查。
- 保留现有 fail_closed 语义，不自动取消或放宽沙盒。外部模型完全访问模式不因不需要的 Codex 缺失被阻断。

## 验证

覆盖路径优先级、Windows 自动发现、显式错误路径、失败缓存恢复、运行上下文隔离、工作区前阻断、事件/运行重试持久化和手动恢复；运行 Python 全量测试及 Windows CI。
