# 实施计划

1. 增加仓库诊断开关、Agent 引用与一次性内置模板，支持重命名联动、删除后跳过。
2. 增加诊断记录、原子去重、运行关联和中断恢复；接入自动 CI 终态分支。
3. 复用 Agent 运行器，加入 CI 诊断上下文、只读日志和源码工具、独立总超时。
4. 将诊断报告补充到受管失败评论，核对当前 CI 防止过期写回。
5. 增加仓库配置控件、内置 Agent 标识、CI 报告展示及复制和运行记录入口。
6. 验证配置生命周期、并发去重、失败隔离、只读工具、日志分页、评论生命周期与 UI 构建，提交并推送。

默认值调整：前后端统一将未配置的失败诊断开关视为开启，明确配置关闭时保持关闭，沿用缺失 Agent 的跳过逻辑；验证旧配置的加载与保存、默认诊断调度和关闭配置，重新构建前端并提交推送。

评论展示调整：

1. 共用失败评论构造函数，从本次 CI 的持久化结果保留失败摘要和原始输出，追加默认折叠的诊断 Markdown。
2. 移除诊断评论中的管理后台链接；分别限制日志和报告大小，截断时保留折叠结构及代码围栏。
3. 回归验证 GitHub/GitLab 同条评论更新、原始信息保留、默认折叠、无后台链接、超长报告及成功后的旧报告保护；提交并推送。
