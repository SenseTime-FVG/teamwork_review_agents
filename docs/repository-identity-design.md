# 仓库名称、ID 与目录迁移

仓库新增可选 `display_name`，仅用于管理界面展示，空值回退到 `id`。规则与运行身份仍使用唯一 ID；名称可以重复，选择器同时展示名称和 ID。

已有仓库支持修改 ID 或基础目录。仅改 ID 时默认迁往原目录同级的新 ID 目录；同时明确填写目录时使用最终目标路径。仅改目录也搬移已有文件。ID 改变时同步搬移按 ID 派生的运行工作区和下载缓存，更新事件快照、运行、活动游标、源版本代次、托管评论及规则引用。运行 ID、事件 ID、原始日志、历史 Prompt 和配置版本保留为审计事实。

目录迁移不能覆盖现有目标或触碰其他仓库目录。成功后不保留旧目录或兼容软链接。修复 linked worktree 双向 Git 路径和保留标记，并同步运行记录中的实际路径。搬移不修改仓库代码、提交和暂存区；依赖中自行保存的绝对路径不做文本替换，迁移后依赖准备快照需要重新生成。

迁移在后台扫描、调度和手动工作区任务空闲时进行。维护期间禁止新工作进入；SQLite 写事务内完成结构化状态更新，磁盘恢复日志覆盖目录移动和受管元数据修改。进程中断后按数据库中的完成标记决定回滚还是清理旧目录，保证配置、状态和目录能恢复到一致版本。新旧 Secret 按旧仓库对象合并，避免改名使脱敏占位丢失真实值。

跨文件系统先复制到目标，数据库提交后清理来源；同文件系统使用重命名。目标冲突、共享目录和包含配置或数据库的路径在搬移前拒绝。
