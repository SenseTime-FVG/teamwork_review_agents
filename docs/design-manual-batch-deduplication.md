# 手动批次去重设计

## 行为

- 一次批量手动触发请求对应一个独立的手动批次，复用规则的 MR/PR、源分支、目标分支去重开关。
- 按规则先匹配再去重；同批次中共享任一已启用去重键的事件只保留原始事件时间最新的一条。分支键仍限定在 Provider 和仓库内。
- 被某条规则去重的事件不会执行该规则，也不会关联获胜事件的 Agent 或 CI；若仍命中其他规则，则照常执行其他规则。全部被去重时显示“未触发”，记录手动批次去重原因。
- 保持 `origin=manual`，保留原事件和直接来源引用，不写扫描记录、不刷新快照或扫描水位。不同点击之间不去重，不取消已有运行。
- 历史重放与“触发最新事件”两个批量入口均适用；单条触发仍是独立手动批次。

## 入队与调度

批量请求先逐项校验，重复或无效项仍单独报错，合法项在一个 SQLite 事务内整体入队，避免调度器看到半个批次。

手动事件新增原始去重时间字段；连续重放时沿用它，直接来源时间仍用于审计。旧手动事件缺少该字段时使用已有来源时间回退。

资源队列按 PR 串行，但分支去重可跨 PR。因此调度手动事件时读取整个批次的持久化事件（包括已经结束的事件），完整规划后仅执行本次已领取的获胜事件。不能只看当前 PR 或待处理事件，否则其他 PR 的获胜事件结束后，旧事件可能再次触发。该查询使用手动批次索引，不受资源队列分页限制。

扫描入口与扫描去重行为保持原样；手动批次不进入扫描待处理集合的预结算。

目标分支事件的保留期清理会跳过尚有活动或可重试事件的手动批次，避免提前删除去重依据；整批结束后仍遵循原有保留期。

## 验证

覆盖原始时间排序、连续重放、跨仓库与跨批次隔离、规则独立去重、混合平台/系统来源、原子入队、已结束获胜事件、资源分页、队列运行中加入批次、无运行关联及 UI 原因说明。
