# 事件处理中状态与本地 CI 实时关联

## 问题

`processing` 覆盖事件领取后、Agent 调度前的处理，不只代表规则匹配。前端将其显示为“规则匹配中”会误导用户。一个批次中的 CI 原先先关联任意首事件，其他真正等待 CI 的事件要等整次 CI 返回后才补关联，导致处理中看不到 CI 详情，甚至把未匹配事件关联到 CI。

## 方案

- 列表状态及筛选统一将 `processing` 显示为“处理中”，不再覆盖成“本地 CI 中”；准备工作区、步骤执行等具体进展仍在详情和日志中展示。其他状态、CI 终态及门禁行为保持不变。
- 编排器只从实际匹配了 `run_preflight` 规则的事件中选择 CI 代表，向执行器传递该批所有受 CI 约束的事件 ID。
- 新建或重试 CI 的数据库事务同时关联全部目标事件；调用方不传批次参数时保留原有单事件兼容。复用已有结果时，在任何可能较慢的状态回写或评论同步之前关联当前事件。
- 仅直接执行 Agent 或未匹配规则的事件不额外关联 CI。同一事件同时匹配直接规则和 CI 规则时仍可关联，不延迟直接 Agent。
- 不增加数据库状态或迁移，不修改运行中的配置和服务，不补写历史事件。保留终态关联的幂等补全及当前 CI 成功、失败、重试策略。

## 验证

覆盖多事件批次、未匹配事件排第一、新建/异常重试/手动换代、缓存复用与状态回写等待、准备与步骤运行期间可读详情，以及无关事件不受影响。前端回归验证“处理中”统一显示、筛选一致、失败终态不被掩盖。
